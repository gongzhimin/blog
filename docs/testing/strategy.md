## 目标与范围

验证六个包的公开契约、跨包交付、阅读器内容和发布副作用。优先保护鉴权、内容完整性、导航一致性、提交计划和异常恢复。规则见 [测试规范](../standards/testing.md)。

本策略区分“必须达到的要求”和“当前已有证据”。测试存在不代表本轮执行；未覆盖的设备、外部服务和人工任务不得由测试数量代替。

## 测试分层

```text
真实 packages/、tests/、docs/
          |
          +-- AST / 类型 / 文档 / 边界扫描
          +-- 测试递归盘点与清单对照
          |
          v
      本轮 Astro build
          |
          +-- Node：模块契约 + 集成产物 + 回环 HTTP
          |
          v
      新启动 Astro preview
          |
          +-- Chromium：几何、可见性、导航、资源错误
          |
          v
      人工阅读任务 / 授权环境验收（分别记录）
```

- 单模块测试位于 `packages/<name>/tests/`。测试可检查本包内部，但不得把别包私有实现当作单测依赖。
- 跨包配置、生成参考、交付资产和 HTML 位于 `tests/integration/`。
- 浏览器位于 `tests/e2e/`；辅助文件位于 `support/`。
- 清单为 `packages/tooling/src/modules.json`。同一集成文件可以关联多个包，执行时去重。
- 工程检查必须扫描真实 package 源码和文档；非法样本注入测试保护这一点。
- 契约编译包含六包公开声明，skipLibCheck=false；编译夹具同时检查合法调用、判别结果和非法参数。声明编译不证明实现符合声明，运行时契约与隔离 tarball 消费另行验证。

## 环境与数据

| 项目   | 固定条件                                                                           | 边界                                                  |
| ------ | ---------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Node   | engines 为 ^22.13.0 或 >=24；npm 锁文件；站点 CI Node 22 / 24，Chromium 在 Node 22 | 本机结果不证明所有兼容版本                            |
| 内容   | 合成条目、固定日期、独立期望；临时仓库请求替身                                     | 不读取生产凭据                                        |
| HTTP   | 127.0.0.1 随机端口、替身 GitHub、受控屏障                                          | 不验证 TLS 或跨进程锁                                 |
| 浏览器 | Playwright Chromium；preview 127.0.0.1:4321；不复用服务                            | 不等于 Safari / 真机                                  |
| 几何   | 文本测量宽 260 / 380 px、高 220 px、容差 1 CSS px                                  | 使用案例声明的固定字体和 CSS                          |
| 导航   | 页面视口 1200 / 390 px；真实多页目录与物理页                                       | 双页模式判定目标页在可见 spread，不强制当前页等于目标 |
| 网络   | 浏览器案例阻断指定远程字体；同源失败默认阻断                                       | 当前不是全网络离线演练                                |
| 退出   | Node 文件 30 秒、浏览器案例 60 秒；零重试                                          | 不证明产品具备运行超时                                |

时间、全局分页配置、临时 DOM、server 和目录在 teardown 恢复。每次浏览器测试先构建，避免旧 dist 提供假证据。

## 用例与断言

### 质量场景追踪

要求定义见 [质量场景](../architecture/context-and-quality.md)。下表为最低验收，不覆盖所有模块细节。

| 要求          | 环境与输入                                                            | 可观察结果与判据                                                        | 自动证据 / 剩余限制                                                  |
| ------------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Q1 内容完整   | 180 组带标识 strong/em、260/380 px                                    | 文本拼接等于源文本，顺序与属性保留，每页独立测量 <=221 px               | pagination-behavior.spec.mjs；不证明所有 HTML                        |
| Q1 导航       | 目录测量 [1,2,2]、[2,1,1]、[1,2,3,3]，循环与预算耗尽                  | 起页=5+目录页数，链接与双向映射一致；失败不提交状态，可恢复             | runtime-lifecycle.test.mjs；真实多页目录另由 browser 用例验证        |
| Q1 文本切分   | 实体、emoji、嵌套链接和含 > 的属性                                    | 前后文本严格相等，属性不丢，代理对不被切断                              | runtime-lifecycle.test.mjs；代码、列表、表格需独立语义矩阵           |
| Q2 内容与配置 | 草稿、非法日期、同日条目、非法几何                                    | 草稿先过滤、稳定排序、输入不改；错误有字段路径                          | integration/public-api、book-config-schema；共享引用不是深不可变     |
| Q3 来源替换   | 合成独立 BookDocument、合法主题、非法来源                             | 不依赖 Astro 装配；输出字段与配置副作用可检查                           | BookBuild API 与集成；不是完整模型校验                               |
| Q4 发布一致   | 同名文章、重复副本、内嵌图片、ref 拒绝、队列屏障                      | canonical 路径/日期保留，正文图片同计划，非强制更新；排队和失败恢复正确 | Publishing webhook/HTTP；真实远程提交另授权                          |
| Q5 交付边界   | 根入口、命名导入/动态导入/私有路径、构建资源                          | 禁止方向和 subpath 被拒绝；正确加载顺序；桌面/移动目标文章可见          | boundaries、集成、navigation E2E；无 Safari 证据                     |
| Q6 可诊断     | runner 失败、重试耗尽、runner/validator 异常、空计划                  | 9 次上限、保留最后错误、异常按契约传播、空计划零调用                    | operations/server-health-check；生产环境另验                         |
| Q7 门禁有效   | 真实包坏文档/非法导入、漏登记/漏文件、非法标记                        | 合法对照过，违规样本失败；动态跳过在运行计数中失败                      | tooling workspace-scan/test-policy/document-contract；不证明所有语法 |
| Q8 阅读任务   | 从六包 README 分别找责任、API、失败条件、验收命令                     | 不翻源码即可定位；离线示例得到声明输出；记录实际路径和卡点              | 独立人工任务；未执行不得标为覆盖                                     |
| Q9 鉴权       | 缺失/空 token、错误 body.token、只有 Authorization、坏 JSON、错误路径 | 配置 fail-closed；403/400/404 符合实际契约，未授权远程调用零次          | Publishing HTTP；体积、速率和 HTML 沙箱仍需独立设计                  |

表中的文件简称分别位于所属包 tests 或 tests/integration。完整用例名、局部矩阵与命令见各包 testing/strategy.md；不以文件存在代替判据。

### 六包最低矩阵

| 包          | 必测正常路径                     | 必测边界与失败                             | 状态 / 副作用                           |
| ----------- | -------------------------------- | ------------------------------------------ | --------------------------------------- |
| Site        | 内容筛选、样式、引语、阅读器载荷 | 空集合、非法配置、非法日期、草稿顺序       | 输入不改，资源组合只归 Site             |
| BookBuild   | 文档到文章、主题与渲染           | 空/单项、非法 theme、缺失 CSS、可选默认值  | 主题无 IO；正文可读本地图片；配置不修改 |
| BookRuntime | 正文/目录/特殊页、缓存           | 校准变化/不收敛、预算、富文本分片          | 失败不提交，reset/清理，真实可见导航    |
| Publishing  | JSON 协议到原子提交计划          | 未授权、解析、规划与远程失败               | 顺序/次数、队列互斥、失败后继续         |
| Operations  | 探针顺序、报告、CLI              | 重试耗尽、空计划、runner/validate 异常     | 不提前停止普通失败，异常语义明确        |
| Tooling     | 正确工程和报告                   | 注入违规、错误路径、空集、漏发现、禁用标记 | 扫描真实包；退出码失败，不自动修复      |

### 变更选择与审查

- 数据/模型/接口：模块正常与负例 + 跨包载荷与类型契约。
- CSS、分页、导航、触摸：上述证据 + 真实 Chromium 几何和可见性。
- HTTP、Git、队列：请求替身 + 回环 HTTP + 受控并发；不自动执行真实发布。
- 部署与恢复：资产/命令/路径审查 + 替身；目标环境执行另授权。
- 门禁、发现或工作流：非法样本注入 + 合法对照 + 实际完整执行。
- 文档：结构检查 + 源码事实核对 + 受影响阅读任务，不能只检查标题。

## 执行步骤

项目根执行：

```sh
npm run check:tests
npm run verify
npm run verify:release
```

1. check:tests 递归比较磁盘与登记，检查非法测试标记。
2. verify 依次执行 format、lint、check:contracts、check:docs、check:boundaries、check:tests、Astro check、build、test:node；任一失败短路。
3. verify:release 再执行 test:e2e；其 pretest 生命周期重新盘点并构建。单独调用 test:e2e 同样使用本轮产物。
4. Node 输出必须可解析且非空，失败/取消/跳过/TODO 均为零；浏览器禁 only、零重试，报告器拒绝动态跳过与预期失败。
5. 审查首个失败、报告和 trace，不删除失败用例换取绿灯。

局部 `node --test <file>` 适用于调试，不代替完整验收；读取 dist 的测试先 build。`npm test` 会先 build；test:node 自身不负责构建。

站点 CI 在 Node 22 / 24 分别运行 verify，并在 Node 22 执行 Chromium；部署依赖两个任务均成功。浏览器成功与失败报告均保留 14 天。Webhook CI 运行 verify 后才打包；它不提供浏览器验收证据。生产验收与自动门禁分开。

## 通过与退出条件

- 受影响契约的正常、边界、错误及状态案例全部通过。
- 完整门禁退出零，测试集非空；失败、取消、跳过、TODO、重试为零。
- 无未处理浏览器异常或同源加载失败；预期断网案例明确范围。
- ESLint 零警告；Astro 零 error、warning、hint。
- 重要预期来自独立规则，不重复调用被测算法生成期望。
- P0/P1 契约违例、漏跑、失真扫描范围均阻断交付；未运行阶段如实标注。
- Q8 和真实环境验收有单独记录才算完成，不用机器绿灯覆盖。
- 未覆盖能力记录责任及补齐触发条件，不声称“全面证明正确”。

## 证据与限制

浏览器结果位于 `test-results/browser-results.json`；失败案例保留 trace、截图和附加证据。Node 保留原始摘要与退出码。变更记录写 Node/浏览器版本、命令、构建来源、结果、缺口和人工任务，不在策略内维护永久测试数量。

`check:packages` 实际打包六包：先在集成 consumer 调用公开任务并编译六包声明及正反夹具，再为每包单独建立 consumer，只安装该包和它声明的 workspace 依赖闭包。安装目录不得为 workspace 符号链接。Runtime 消费测试显式添加 JSDOM 作为宿主夹具，不把它当 Runtime 依赖。Publishing/Operations 仅导入，不执行生产任务。Tooling 的显式 root 是被检查仓库，不是依赖链接。安装可读取 npm 缓存或 registry；每个子进程最多 120 秒，成功/失败均清理临时目录。这不验证脱离根宿主配置后的独立 Astro 应用构建。

当前限制：

- 浏览器仅 Chromium；无 Safari/iOS 真机、不同字体和慢图片完整矩阵。
- 代码块已增加换行、token 属性和高度案例；列表、表格、超大图片和更多实体组合不由这些案例全面证明；这些类型变化必须补独立案例。
- 导航短键碰撞、分页共享配置并发及资源加载后重排仍需单独设计和测试。
- 发布替身不证明真实 ref 更新、响应丢失后恢复或生产权限。
- 没有资源耗尽、性能基线、覆盖率阈值或生产恢复演练；不能补造数值。
- 阅读任务须独立执行，源码熟悉者的自查不能标为新贡献者验收。

这些限制不豁免已知契约错误。详见 [风险台账](../architecture/evolution.md) 和 [部署验收](../operations/deployment.md)。
