## 问题与目标

在真实的 Web 阅读环境下，文章文本长度极不固定，且各客户端设备的渲染字族、系统 DPI、视口物理宽度以及图片加载时机均存在显著差异。

静态构建期虽然能够生成语义化 HTML，但由于缺乏客户端布局引擎的实际度量，根本无法预知文本与富媒体在具体设备上的实际折行与物理排版高度。

若直接将整篇长文注入单一页面，会导致正文大面积被容器裁切；而若仅凭字符数量强行截断，又会严重破坏 HTML 嵌套标签的语法闭合与代码公式的语义结构。

Book Runtime 使用浏览器测量正文，将长文切分为适配当前尺寸的页面序列。设计约束是保持正文顺序，记录每篇文章的起始页，并将封底放在正文之后。

URL 使用构建阶段生成的 key 定位文章；源 id 才是数据身份，有限长度的 key 不保证无碰撞。分页假设测量期间内容和字体稳定，不保证任意 HTML 或异步加载资源都无溢出。

本模块明确将在线所见即所得编辑、源内容网络抓取、跨源不受信 HTML 深度净化以及底层渲染器深度改造列为非目标。运行时模块仅作为被动消费端，直接接收构建期注入的结构化阅读数据，杜绝直接读取 Astro 静态内容集合。

## 范围与约束

在质量场景与容错策略上，运行时对不同排版刺激设立了明确的预期响应与当前证据边界：

| 刺激源                                | 预期系统响应                                 | 当前证据与已知局限                                                                                      |
| ------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 包含 `<strong>`/`<em>` 的超长段落     | 分页切分后保持文本顺序无损，标签闭合         | Playwright 回归测试验证了两种视口下的全文连续性与高度约束，但嵌套强调跨页时的语义完备性仍需持续补充用例 |
| 目录篇目较多导致超出单页              | 目录动态扩展后，各文章的实际物理起页相应平移 | 初测后最多校准 8 轮；页数稳定才提交，重复候选或预算耗尽抛错；生命周期测试覆盖增长、缩减和失败隔离       |
| 用户携带 `?post=<key>` 访问           | 精确跳转至目标文章的第一个物理页面           | 由控制器与适配器协同维护文章哈希键与物理页码映射表                                                      |
| 视口缩放跨越移动端断点                | 切换至对应的单页/双页几何尺寸重新初始化      | 监听 `resize` 事件，防抖延迟 500 ms 后触发整页重载刷新                                                  |
| 外部图片或自定义 Web 字体晚于测量到达 | 保持页面基本可读，允许渐进渲染               | 测量引擎未挂起等待 `document.fonts.ready`，属于已知弱点，依赖外部资源尽早固化尺寸                       |
| 分页计算发生未捕获异常                | 阻止全屏白屏，降级提供基础导航               | 异常分支安全回退至初始目录展示，但不保证正文完整可读                                                    |

在测量与资源生命周期方面，`PaginatorCore` 的配置为内存共享状态，每次测量前必须克隆快照。测量节点使用的尺寸以 CSS 像素表示，必须与外层显示容器的盒模型保持严格一致。

由于测量逻辑对带天然宽高的顶层 `<img>` 仅同步写入属性，并未异步挂起等待 `img.onload` 或字体解码完成，因此当前稳定运行的前提是前置页面已通过静态 HTML 声明了图片尺寸并预置了核心字族。

## 内部组成

运行时内部遵循严格的分层架构与 DOM 所有权边界划分，整体调用与数据流向如下图所示：

```text
Site 页面 -> Assets.astro -------> 顺序加载第三方 vendor 依赖
BookShell -----------------------> 注入测量 CSS 与 book-data
                 |
                 v
            browser-entry --------> 初始化 book-app 顶层控制器
                 |
                 v
          api/index.mjs ----------> 对外暴露受控接口与生命周期方法
                 |
    +------------+------------+
    |                         |
PaginatorCore (配置快照)    Paginator (测量与切分编排)
    |                         |
    |                         +---> Splitters (文本/表格/列表/代码拆分器)
    v                         |
Orchestrator (页轴编排/缓存) <--+
    |
    v
TurnAdapter (事件代理与页节点创建) --> 驱动第三方 Turn.js 翻页引擎

Site 页面 -> Cursor.astro --------> 挂载独立光标跟随 DOM (生命周期与书籍解耦)
```

各内部协作单元的职责边界划分如下：

1. **PaginatorCore**：管理测量视口的基准配置，负责创建 body 下的离屏测量容器；调用者持有 measure 并负责移除；
2. **Paginator**：核心分页调度器，负责遍历文章并驱动各专用拆分器计算文本截断点，产出单篇文章的物理页切片数组；
3. **Splitters**：包含文本分段、有序/无序列表切分、HTML 表格按行切分以及代码块切分的原子算法集合，尝试保持元素结构；跨页语义需专门测试；
4. **Orchestrator**：全书编排中枢，负责管理全书物理页缓存、动态生成书籍目录、计算罗马数字页码与阿拉伯正文页码映射，以及控制封底插入位置；
5. **TurnAdapter**：封装与第三方翻页库的底层交互，负责在翻页时按需提取缓存中的 HTML 挂载至对应 DOM 节点，并代理触摸、点击与按键事件；
6. **book-app**：前端总控引导程序，负责读取 DOM 中注入的构建期配置、判断移动端断点、在脚本就绪后启动同步分页并在失败时执行降级逻辑。

## 数据与接口

系统核心数据模型包含构建期输入、分页中间态与最终页轴映射：

- **输入文章实体**：包含文章标识 `key`、标题 `title`、格式化日期 `dateStr` 以及富文本正文 `bodyHTML`。由于正文 HTML 直接注入 DOM 容器参与测量，上游构建期内容的安全性是先决条件。
- **页面体系与拓扑分层**：系统将整书物理页划分为四个清晰的抽象层级：
  1. **前置特殊页**：物理页 1（封面 `FRONT_COVER`）、物理页 2（封二 `INSIDE_FRONT_COVER`）、物理页 3（扉页正面 `TITLE_PAGE`）、物理页 4（扉页反面/出版说明 `IMPRINT_PAGE`）；
  2. **动态目录页**：物理页 5 开始，占 $T$ 页（`TOC`），页脚展示大写罗马数字；
  3. **正文主体页**：从物理页 $bodyStart = 5+T$ 开始，到 $bodyEnd = bodyStart + M - 1$（`BODY`）；
  4. **后置特殊页**：若 $bodyEnd$ 为奇数，自动补入 1 页对齐尾衬页（`ALIGNMENT_ENDPAPER`）以维持偶数跨页；紧随物理倒数第二页（封三 `INSIDE_BACK_COVER`）和物理最后一页（封底 `BACK_COVER`）。
- **物理页与显示页映射**：系统内部维护三套用途不同、共享物理页计算结果的索引：
  1. `physical → HTML`：物理页号到实际承载内容的映射。物理页 1、2、N-1、N 为书壳节点，物理页 3、4、目录页、正文页和可选尾衬页由 `pageCache` 动态注入；
  2. `article key → physicalStartPage`：文章导航键到物理起始页的索引，支撑 `?post=<key>` 深度链接跳转；键碰撞可能使定位不明确；
  3. `physical → displayPage`：物理页号到用户可见页脚的映射。**页码统计隔离不变量**：前四页、目录页、对齐尾衬页和最后两页均**不计入**正文页码统计与计数；正文页面是全书唯一参与页码统计的范围，显示页码严格从 1 递增至 $M$（$totalBodyPages = M$）。
- 运行时对外暴露 `getPageKind`、`isSpecialPage`、`isCountedPage`、`physicalToBodyPage`、`bodyToPhysicalPage` 及 `getPageLayout` 等查询与转换 API。

包根仅导出 `paginateBook(payload)`，将配置、正文分页、目录校准和物理页映射收敛为一次任务。结果复制为可消费的页数组和映射，不暴露缓存实例。Astro Assets 子路径负责浏览器资源加载和阅读器启动；Paginator、Orchestrator 与 TurnAdapter 都是内部实现。

外部调用者不得绕过 API 规范直接导入 `internal/` 目录下的私有模块。

## 关键流程

运行时生命周期包含初始化、正文测量、有界目录校准、DOM 装配及事件处理：

```text
第三方脚本加载完成 -> 触发 browser-entry -> 读取 DOM 配置并判断移动断点
                                                 |
                                                 v
                                   调用 PaginatorCore.configure()
                                                 |
                                                 v
                                        执行 paginateAll()
                                                 |
        +----------------------------------------+---------------------------------------+
        |                                                                                |
[第一阶段：正文测量]                                                             [第二阶段：目录排版与页轴校准]
遍历各篇文章，挂载离屏测量 DOM                                                  以预估的正文起点生成目录 HTML
调用对应 Splitter 拆分溢出的元素                                                  将目录送入 Paginator 测量实际占用页数
生成每篇文章的独立页面切片数组                                                  最多校准 8 轮；稳定后统一正文起页
        |                                                                                |
        +----------------------------------------+---------------------------------------+
                                                 |
                                                 v
                                    将全书页面存入 Orchestrator 缓存
                      (物理 3 扉页、4 出版说明、5~ 目录、正文页及奇偶对齐尾衬页)
                                                 |
                                                 v
                               调用 TurnAdapter.mount() 挂载 Turn.js 容器
                                                 |
                          +----------------------+----------------------+
                          |                                             |
                  挂载成功 (返回 true)                           容器尺寸为 0 (返回 false)
                          |                                             |
                          v                                             v
                  进入可阅读就绪态                                10ms 后重新调用 loadApp；无固定重试上限
                          |
                          v
         监听用户翻页 / URL 变化 / 视口缩放跨断点 (触发防抖 reload)
```

在分页失败路径上，`book-app` 会捕获 `paginateAll()` 抛出的异常，立即调用缓存实例的 `reset()` 清理半成态缓存，并在控制台记录错误栈，同时强制将物理第 5 页渲染为初始目录列表，保留目录列表；它不保证正文页恢复。

目录校准重复候选或耗尽预算时在缓存与封底提交前抛错，直接 API 调用者可修正测量条件后重试；应用仍走上述异常回退。校准成功后不再测量目录，后续资源改变仍可能使布局失效。

## 设计取舍

- 每个 PageCache 持有自己的完整分页结果与封底 style 引用。命中直接复用结果，避免把缓存条目数量误当总物理页数；
- reset 只释放该实例持有的资源和导航状态，不猜测插件拥有的 DOM。测量容器由创建调用持有，在 finally 中释放；
- 局部查找 inner 保留页面上已有同 ID 节点。

在系统架构演进中，针对核心技术选型进行了深入权衡：

1. **浏览器运行时动态切分 vs. 构建期静态切分**：虽然构建期预先分页能够消除客户端计算白屏时间，但完全无法适应多端屏幕尺寸与系统自定义字体的排版差异。因此，我们选择在浏览器端动态度量，以客户端同步测量成本适应当前视口；耗时随正文和布局复杂度变化，目前没有性能预算证据。
2. **有界校准 vs. 固定二次测量或无限迭代**：固定二次测量无法处理重建目录后页数变化，无限迭代又不能保证终止。采用初测加最多 8 轮候选校准，页数一致后才提交缓存与导航；重复候选或预算耗尽抛错。代价是额外同步布局测量，8 轮只限制次数，不承诺耗时或收敛。输入 key 无冲突仍是导航条件，碰撞检测未实现。
3. **断点切换执行整页 Reload vs. 原地热重排**：跨越移动端断点时，书本从双页翻页切换为单页滑动，底层 Turn.js 实例的 DOM 结构与动画模型完全不同。由于本模块没有公开适配器卸载接口，原地重置极易导致内存泄漏与事件重复绑定。采用延迟防抖的 `location.reload()` 虽牺牲了微小的瞬态体验，让当前页面的缓存和事件随页面销毁；代价是重载及阅读位置恢复。
4. **特殊页面分层抽象与首末空白页消除**：
   - _首端空白消除_：经典实体书开卷必然先见扉页与出版说明。历史实现中物理页 3、4 留空作为待翻页容器，未做任何语义填充，导致开卷翻页时视觉呈现为纯空白突兀页；`BookShell.astro` 错误地将硬封面精灵背景挂在物理页 3 上又造成纸张材质撕裂。重构在构建期（`BookShell.astro` 静态预渲染骨架）与运行时（`renderTitlePage`、`renderImprintPage`）闭环注入优雅排版，翻开封面即见题记，彻底消除首页空白；
   - _末端空白消除_：正文主体可能结束于左页（偶数）或右页（奇数）。若正文在右侧奇数页结束，若不加处理直接紧跟封三，会导致双页视图中封三被排在右页从而撕裂书籍封底结构并产生多余空白。重构在 `bodyEnd % 2 !== 0` 时自适应插入 `ALIGNMENT_ENDPAPER`（对齐尾衬页），使封三始终闭合在左侧偶数页；
   - _页码统计隔离_：严格界定只有正文页属于被计数的“阅读正文”，无论动态目录扩张为几页、是否插入对齐尾衬，正文页码均严格保持 $1 \sim M$ 不变，向读者呈现与实体书一致的专业页码体系。
5. **移除强制打断实现单次流畅翻壳**：
   - 历史移植代码为了模拟 2012 年旧演示的某些边缘行为，在翻到第 1 或第 2 页时插入了 `book.turn('page', 2).turn('stop').turn('page', page)` 强制翻停与再翻代码，使得动画在翻动途中被粗暴切断并触发二次动画，表现为封面/封壳“翻了两次”的视觉瑕疵；
   - 彻底移除打断 hack，将翻页调度完全交由 Turn.js 原生状态机平滑完成；同时修正 `numberOfViews` 为 `Math.floor(pages / 2) + 1`，彻底根除双封壳视觉跳动问题。

## 失败与边界

开发与维护过程中需重点关注以下异常边界与限制条件：

1. **元素拆分死循环防护**：正文元素调度主循环设有3000步预算，分割余量重新插入队列也计入步数；已完成3000步且仍有待处理元素时抛明确 Error，不交付截断成功结果，finally 释放本调用测量容器；
2. **不可拆分的大尺寸块**：对于包含固定宽高的复杂表格、超大代码块或内联 SVG，若其自身高度超出单页可用最大高度，拆分器将无法继续细分，仍可能溢出，不能保证裁剪程度；
3. **缓存重入限制**：`Orchestrator` 的缓存机制假定书籍内容在单次会话内不可变，`paginateAll()` 执行后若未显式调用缓存实例的 `reset()`，再次调用将复用首次的完整七字段结果和缓存，不会触发真实 DOM 重新度量；
4. **自愈与降级能力**：当 DOM 翻页容器初始化尺寸异常时，适配器通过有节制的延时重试避免即刻报错；在分页彻底崩溃时，降级目录能够兜底提供最基础的篇目索引。

## 验证与演进

封面装饰的收敛由实际插件状态驱动：end/turned 可能早于最后一项 motion 移除，不能只在一次延迟中判断。适配器逐帧观察，空闲时同步端点 class、depth 和 slider；新 start/turning 取消旧观察，节点移除或插件销毁后停止。该观察不提供插件故障的超时保证。受控 motion 回归验证回调后仍有运动的场景；完整预览测试不覆盖快速离开角点的所有第三方状态路径。

当前证据及未覆盖范围如下：

- **逻辑单元测试**：`packages/book-runtime/tests/turnjs-adapter.test.mjs` 与 `packages/book-runtime/tests/paginator-config.test.mjs` 分别核对适配器静态源码约定及共享配置快照行为，不证明实际拆分高度；与构建书壳和 vendor CSS 的配对断言另在 `tests/integration/turnjs-integration.test.mjs`；
- **端到端集成测试**：`tests/e2e/pagination-behavior.spec.mjs` 与 `tests/e2e/homepage-layout.spec.mjs` 在无头 Chromium 环境中验证260/380px测量宽度的富文本连续性及高度，另有传统首页布局测试；pagination-behavior 另验证真实多页目录、1200/390px 目录点击和深链接；test-pages-debug 验证特殊页、封面类型与往返 spread。文本和代码分片新增实体、Unicode、属性和换行回归。键盘翻页仍无独立完整场景。

- 未来演进方向包括：引入 `ResizeObserver` 替代全局 `resize` 监听，探索更细腻的容器级局部重排方案；
- 在拆分算法中补充对孤行/孤字（widows/orphans）的排版控制规则；
- 当未来计划支持更丰富的富文本排版组件时，逐步将底层的 Turn.js 适配层抽象为标准化的翻页器驱动插件接口。
