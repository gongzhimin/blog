# 首页技术人文杂志设计规格

## 1. 范围与目标

本规格只覆盖博客首页，不扩展到归档页、文章页和 About 页的具体版式。

本规格是首页的最新专项规范。与 `2026-06-20-blog-ui-design.md` 中的首页描述发生冲突时，以本规格为准。

首页采用自上而下的线性结构：

1. 导航栏
2. 头部区
3. 内容区
4. 页脚

桌面端应在常规视口中尽量完整展示首页，形成一张完整的杂志目录页。移动端允许自然滚动，并将桌面的双页书籍转换为两张纵向排列的完整纸页。

设计气质为克制的技术人文杂志。杂志感来自排版、纸张、书脊、留白和目录秩序，不依赖卡片墙、封面大图、厚重阴影或翻页动画。

## 2. 页面骨架

### 2.1 桌面端

页面最大内容宽度为 `1080-1160px`，四个区域共享同一条水平对齐基线。

```text
导航栏        约 56-60px
头部区        约 140-170px
双页内容区    占据主要剩余空间
页脚          约 96-112px
```

在高度不低于约 `720px` 的常规桌面视口中，首页应尽量完整出现。视口不足时允许页面正常滚动，不通过压缩字号、裁切内容或重叠区域强行塞入一屏。

### 2.2 移动端

移动端按以下顺序纵向排列：

1. 吸顶导航栏
2. 紧凑头部区
3. 完整生活纸页
4. 完整技术纸页
5. 每日一句与版权

移动端不要求一屏展示完整首页。所有内容必须保持可读，不使用横向滚动。

## 3. 导航栏

### 3.1 内容

桌面端结构：

```text
ZHIMIN                 技术  生活  关于  RSS  主题切换
```

- `ZHIMIN` 链接到首页，既是作者署名，也是返回首页入口。
- `技术` 链接到技术归档页。
- `生活` 链接到生活归档页。
- `关于` 链接到 About 页。
- `RSS` 链接到 RSS Feed。
- 主题切换使用图标按钮，并提供可访问名称和悬停提示。

移动端保留 `ZHIMIN`、RSS、主题切换和菜单图标。技术、生活、关于收进菜单。

### 3.2 行为

- 首页、归档页和 About 页的导航栏吸顶。
- 文章阅读页的导航栏不吸顶，随正文自然离开视口。
- 吸顶导航使用不透明实体背景和底部细分隔线，避免页面内容透出。
- 滚动时导航栏不缩放、不改变高度、不添加复杂动画。

## 4. 头部区

头部区使用紧凑的作者宣言，不重复显示 `ZHIMIN`：

```text
写技术，也记录技术之外的生活。
软件、工具、思考与日常。
```

### 4.1 桌面端

- 高度约 `140-170px`，不超过可用首屏高度的四分之一。
- 主句使用约 `40-48px` 的中文衬线字体。
- 副句使用约 `16px` 字号和较弱颜色。
- 内容与导航及书页左边缘对齐。
- 不放头像、按钮、年份、标签或向下滚动提示。
- 底部使用一条细线结束头部区。

### 4.2 移动端

- 主句缩至约 `30-34px`，允许自然换行。
- 保持与纸页一致的页面左右边距。
- 不为制造首屏效果而压缩文字。

## 5. 内容区：打开的书

### 5.1 桌面端

内容区表现为一本水平摊开的书：

- 左页是 `生活随笔`。
- 右页是 `技术笔记`。
- 两页等宽，拥有一致的页眉、目录区域和页脚位置。
- 两页之间使用窄书脊、轻微内侧阴影和克制的纸色差。
- 外侧不使用圆角卡片、厚重边框、卷页或拟真翻页效果。

每页展示最近六篇文章，按发布日期倒序排列。页尾分别提供：

- `全部生活文章 →`
- `全部技术文章 →`

### 5.2 目录行

目录行沿用书籍目录语法：

```text
文章标题 .................... 2026.06.20
```

- 标题位于左侧，日期位于右侧。
- 标题与日期之间使用点线引导。
- 日期格式为 `YYYY.MM.DD`。
- 整行可点击，并具备清晰的键盘焦点状态。
- 悬停或聚焦时，标题、点线和日期共同增强对比度。
- 长标题优先收缩点线空间；必要时标题最多显示两行。
- 文章不足六篇时展示实际数量，不添加空白占位条目。

### 5.3 移动端

桌面的左右书页改为两张纵向排列的完整纸页：

1. 生活页
2. 技术页

每张纸页都保留：

- 完整四边轮廓
- 独立纸色与轻微投影
- 页眉、目录正文和页脚
- 稳定内边距
- 接近书页的纵向比例

两张纸页之间保留约 `24px` 间距。移动端每页只展示最近三篇文章，页尾仍保留全部文章入口。

移动端日期优先使用 `MM.DD`。标题最多两行，点线占据标题与日期之间的剩余空间。

首页统一读取每类最近六篇文章；移动端仅隐藏第 4-6 篇，不维护两份文章列表。

## 6. 页脚：每日一句

页脚采用左对齐的双语题记：

```text
────────────────────────────────────────

“The quieter you become, the more you can hear.”
你越安静，越能听见真正重要的声音。

© 2026 ZHIMIN
```

### 6.1 视觉规则

- 顶部使用一条细分隔线。
- 不显示“每日一句”标签。
- 不显示句子作者、发布日期或来源。
- 英文原句使用略大的衬线字体，可使用轻微斜体。
- 中文译文字号稍小、颜色稍弱。
- 版权信息显示在题记下方，使用更小字号。
- 桌面端为英文和中文各预留最多两行，总高度约 `96-112px`。
- 短句不拉伸、不放大，保持左对齐。
- 移动端沿用相同结构并允许页脚自然增高。
- 版权年份由构建时的当前年份生成；当前呈现为 `© 2026 ZHIMIN`。

### 6.2 内容长度契约

每日一句必须符合以下限制：

- 英文原句最多约 140 个字符，最多两行。
- 中文译文最多约 70 个汉字，最多两行。
- 不截断句子，不使用省略号隐藏内容，不动态缩小字号。
- 内容超过限制时重新获取另一条。
- 无法获取合格内容时使用本地备用句。

### 6.3 API 更新与回退

当前博客采用 Astro 静态构建。每日一句不在浏览器中直接请求第三方 API，以避免内容闪烁、布局跳动、跨域错误和第三方服务暴露。

更新流程如下：

1. 每日定时任务调用每日一句 API。
2. 将响应规范化为英文原句和中文译文。
3. 校验字段完整性与长度限制。
4. 合格内容写入站点内的日期缓存数据。
5. 触发静态站点重新构建和部署。
6. API 超时、返回错误、翻译缺失或内容过长时，使用本地备用句完成构建。

同一天所有访客看到同一句内容。页面初始 HTML 已包含最终句子，不显示骨架屏，也不在加载后替换文本。

每日一句数据层只向页面暴露以下稳定结构：

```ts
type DailyQuote = {
  date: string;
  english: string;
  chinese: string;
  source: "api" | "fallback";
};
```

`source` 只用于诊断，不在页面中显示。

## 7. 响应式与可访问性

- 桌面双页在移动断点下切换为两张纵向纸页。
- 导航、目录行、全部文章入口和主题切换均支持键盘操作。
- 图标按钮提供可访问名称。
- 文本和背景保持足够对比度。
- 用户启用减少动态效果时，不执行淡入或位移动画。
- 页面缩放到 200% 时不出现文字遮挡、水平滚动或不可操作控件。
- 较长的中英文标题必须在其容器内换行，不覆盖日期。

## 8. 验证方案

视觉验证至少覆盖以下视口：

- `1440x900`：确认桌面首页完整展示和整体留白。
- `1366x768`：确认常见笔记本视口中四个区域仍保持清晰。
- `1280x720`：确认较矮桌面视口不会发生重叠；必要时允许轻微滚动。
- `390x844`：确认两张完整纸页纵向排列，每页只显示三篇。
- `360x800`：确认长标题、日期、菜单和每日一句不会横向溢出。

内容状态至少覆盖：

- 每类文章多于六篇。
- 每类文章少于六篇。
- 标题为短标题。
- 标题达到两行长度。
- 每日一句接近长度上限。
- 每日一句很短。
- API 超时、数据缺失、译文缺失和内容过长。

自动化测试应覆盖文章排序、桌面六篇与移动端三篇的呈现规则、日期格式、每日一句校验和备用内容回退。浏览器截图用于确认书页比例、中缝、文本换行、首屏高度和移动端纸页完整性。

## 9. 验收标准

1. 桌面端首页严格按导航、头部、双页内容、页脚的顺序呈现。
2. 常规桌面视口中尽量完整看到首页；较矮视口允许自然滚动。
3. 桌面端生活和技术各显示最近六篇，日期使用 `YYYY.MM.DD`。
4. 移动端显示两张完整纸页，生活在前、技术在后，每页最近三篇。
5. 目录具有标题、点线和日期的书籍目录结构。
6. 首页导航吸顶，文章阅读页导航不吸顶。
7. 页脚只显示英文原句、中文译文和版权，不显示句子作者。
8. 每日一句过长或 API 失败时使用合格备用句，页面不截断、不跳动。
9. 首页不出现卡片墙、封面主图、向下滚动提示或厚重拟物效果。
10. 桌面和移动端均无文本重叠、控件溢出和不必要的横向滚动。
