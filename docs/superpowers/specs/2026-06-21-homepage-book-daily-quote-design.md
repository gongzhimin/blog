# 首页书本质感与每日一句设计

日期：2026-06-21

## 目标

在不改变首页“双页文章目录”信息结构的前提下，让内容区更接近日常生活中自然摊开的平装书，并将页脚每日一句改为自动获取、静态生成和可靠降级。

本次改动继续保持 Astro 静态站点架构。浏览器不直接请求第三方接口，服务器不新增常驻服务。

## 视觉方向

首页书本采用“B1 日常平装书”方向：

- 书脊位置视觉下陷，左右纸面向外自然舒展。
- 外侧页角和底边有轻微弧度，不呈现机械矩形。
- 页面底部显示克制的纸张层叠厚度。
- 整本书具有柔和、扩散的桌面环境阴影。
- 左右页只使用微小静态透视，不添加悬停翻页动画。
- 正文和文章链接保持稳定、清晰，不随交互移动。

弧度主要通过页面轮廓、渐变、伪元素和阴影模拟。不得使用会明显扭曲正文的强透视，也不得追求写实翻页特效。

## 响应式行为

桌面端在足够宽的视口中显示完整双页书本：

- 左页为生活随笔，右页为技术笔记。
- 双页共享中央书脊和整体投影。
- 书本底部使用伪元素表现纸页厚度与轻微弧线。

移动端继续采用纵向单页布局：

- 移除 3D 透视和页面旋转。
- 不显示会挤压内容的书脊和页厚效果。
- 保留纸张颜色、边框与轻微阴影，维持阅读优先。

`prefers-reduced-motion` 不需要额外分支，因为书本本身没有动画。

## 每日一句数据模型

每日一句静态数据写入 `src/data/daily-quote.json`，结构为：

```ts
type DailyQuote = {
  date: string;
  english: string;
  chinese: string;
  author: string;
  source: "shanbay" | "youdao" | "fallback";
};
```

页脚按以下顺序展示：

1. 英文原文。
2. 中文译文。
3. 作者署名，格式为 `— 作者`。

作者为空时不渲染署名，不显示第三方接口品牌。

## 数据获取

新增独立 Node.js 脚本负责获取和规范化数据，组件不包含网络逻辑。

数据源优先级：

1. 扇贝每日一句接口。
2. 有道 `infoline` 接口中的当日“壹句”。
3. 仓库中上一条有效的 `daily-quote.json`。

扇贝响应直接读取英文、翻译、作者和日期。有道响应必须限定请求日期，并从对应日期数组中选择当日、类型为“壹句”的有效记录；优先选择带来源或作者的每日内容，避免误取重复的专栏卡片。

## 校验与错误处理

写入前必须校验：

- 日期为 `YYYY-MM-DD`。
- 英文和中文均为非空字符串。
- 英文不超过 500 个字符，中文不超过 500 个字符。
- 作者不超过 120 个字符；缺失时规范化为空字符串。
- 响应必须与请求日期一致，不能用未来或过期接口内容冒充当日内容。

每个请求设置超时，并在失败时输出明确日志。两个接口都失败或返回无效数据时：

- 保留现有 JSON，不覆盖为无效内容。
- 构建和部署继续执行。
- 工作流日志标记本次使用旧数据。

## 自动化与部署

扩展现有 `.github/workflows/deploy.yml`：

- 保留 `main` 分支相关文件变更时的部署触发。
- 新增定时触发：`15 22 * * *`，对应北京时间每日 `06:15`。
- 定时运行时先执行每日一句获取脚本。
- 数据发生变化时，由 GitHub Actions 提交并推送更新后的 JSON。
- 无论 JSON 是否变化，同一次工作流继续安装依赖、构建并部署到服务器。

定时提交使用工作流自带的 `GITHUB_TOKEN`。由该令牌产生的提交不会再触发另一个 `push` 工作流，因此获取、提交、构建和部署必须在同一次工作流中完成。

普通代码或内容推送不主动请求第三方接口，只使用仓库内已提交的每日一句数据，以免每次发布文章都改变页脚内容。

## 组件边界

- 获取脚本：网络请求、超时、解析、校验、回退和写文件。
- `daily-quote.json`：构建期唯一数据输入。
- `DailyQuote.astro`：只负责英文、中文和可选作者的展示。
- `index.astro`：读取 JSON 并传递属性。
- `home.css`：负责书本外观和响应式降级。
- GitHub Actions：负责定时调度、提交、构建和部署。

各部分不相互泄漏职责，接口变化只需修改获取脚本和对应测试。

## 测试

自动化测试至少覆盖：

- 扇贝有效响应的解析和规范化。
- 扇贝失败后切换有道。
- 有道重复记录的筛选。
- 两个数据源均失败时保留现有 JSON。
- 日期、空文本和长度校验。
- 作者存在和缺失时的页脚输出。
- 桌面端包含书脊、页厚、环境阴影所需样式。
- 移动端取消透视和旋转。

构建、现有首页测试和完整测试套件必须通过。

## 非目标

- 不实现真实翻页、拖拽、悬停开合或页面动画。
- 不在浏览器中调用每日一句接口。
- 不把第三方图片、音频或分享链接引入首页。
- 不新增数据库、缓存服务或服务器定时任务。
- 不改变现有文章目录的数据来源和分类结构。
