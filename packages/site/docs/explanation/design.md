## 问题与目标

在现代静态博客架构中，同一篇文稿资产需要同时满足三种不同的阅读场景：单篇独立 URL 访问（便于搜索引擎收录与外链分享）、按生活/技术分类的经典目录检索（便于快速扫读与归档定位），以及连续沉浸式翻阅（模拟纸质拟真翻页书）。

这三种呈现模式的交互形态与视觉布局截然不同，但文稿的底层身份、草稿可见性以及排序规则必须严格保持一致。各页面重复决定草稿与日期政策会增加规则漂移风险；目前书籍适配器与传统目录函数的前置条件仍不同。

Site 模块作为博客前台应用的核心边界，承担着统一内容政策与多端页面组合的关键职责。

本模块的设计目标是在静态内容资产边界确立严格的可见性、合法性校验与排序准则，并将经过草稿过滤与日期校验的内容模型规范化交付给通用的书籍渲染引擎与经典 Astro 页面。

通过物理集中所有页面路由、组件布局、视觉样式与站点配置，本模块将底层的通用书籍排版能力和客户端运行时组合成完整的博客网站，同时向通用书籍模块隔离 Astro 集合与路由实现的细节。

## 范围与约束

在业务边界与输入约束上，Site 模块遵守以下设计规范：

1. **受信内容假设与字段类型约束**：文稿源文件假定来自版本受控的受信写作资产，Astro Content Collections Schema 负责执行基础的字段类型校验，模块内部不重复集成 XSS 净化器；
2. **严格的草稿过滤与日期有效性**：在构建书籍模型时，必须前置过滤所有声明为 `draft: true` 的文稿；对于非草稿文稿，其发布日期必须能够解析为合法的 `Date` 对象，任何无效日期将直接触发构建中断，严禁静默回退为当前系统时间掩盖问题；
3. **确定性日期优先级与排序不变量**：文稿发布时间遵循明确的优先级规则：`pubDatetime ?? date`。若声明了非空的 `pubDatetime` 但其解析失败，不得静默降级为 `date`；文稿一律采用稳定的倒序排列，当时间戳完全相同时保留原数组顺序，且合并前生活分类（`life`）优先于技术分类（`blog`）；
4. **展示过滤与正文完整性分离**：经典视图中的窄屏隐藏策略仅用于目录项视觉排版优化，严禁因视口隐藏而影响正文内容生成或改变书籍排版篇目。

## 内部组成

模块内部按照单一职责原则划分业务层级，核心结构与依赖关系如下图所示：

```text
Astro Content Collections (生活与技术文稿资产)
                     |
                     v
+-----------------------------------------------------------+
| Site 内部构建与维护职责（不是公开导出清单）               |
|   |-- 内容源适配器 (sources/) -----> 过滤草稿并构建 BookDocument |
|   |-- 目录与归档服务 (catalog/) ----> 投影经典双栏与归档列表     |
|   |-- 视觉配置验证 (config/) -----> 校验 Schema 并注入 CSS 变量 |
|   +-- 每日一句边界 (quotes/) -----> 请求第三方格言并执行多级降级 |
+-----------------------------------------------------------+
                     |
                     v
页面组合层 (pages/ 与 layouts/components/)
  |-- / (拟真翻页书首页) ----------> 组合 BookShell + Runtime Assets
  |-- /classic (经典双栏目录) ------> 消费 catalog 投影并注入流式排版变量
  |-- /blog/[slug], /life/[slug] -> 渲染单篇文章与评论组件
  +-- /rss.xml.js -----------------> 导出标准化订阅聚合
```

各内部子系统的核心职责说明：

- **数据源适配器（`sources/`）**：负责遍历 Astro 集合，执行严格的日期提取与草稿剔除，将异构文稿映射为通用的 `BookDocument` 标准载荷；
- **目录服务（`catalog/`）**：负责为经典首页和归档页生成轻量级文章索引列表，包含紧凑日期格式化与窄屏自适应隐藏计算；
- **配置与样式引擎（`config/` 与 `styles/`）**：负责校验 `homepage-config.json`，并将断点间距、字体族与亮/暗色阶映射为 CSS 自定义属性；
- **格言同步服务（`quotes/`）**：由句子更新 CLI 请求外部每日一句接口，页面构建只读取仓库快照，管理超时中断并在网络故障时安全回退至上一次快照。
- **浏览器交互（internal/turnjs-adapter.js、book-app.js）**：消费 Runtime 的页数组与映射，装配 Turn.js 并处理触摸、目录、深链接和动画。适配器不属于 Runtime API；它使用 SiteReader 私有命名空间。

六种特殊页的模板、挂载类、插画角色和专用主题 CSS 集中在 `internal/presentation/special-pages/`。书壳只负责挂载，Runtime 只负责实际页号；初始 HTML 与数据岛中的 HTML 使用同一份生成结果。独立编辑位置与取舍见 [六页设计](special-pages.md)。

## 数据与接口

系统在内容流转过程中涉及如下关键数据形态：

- **单篇文章原始模型（`Post`）**：包含文稿标识 `id`、Markdown 原文 `body` 以及前置元数据 `data`（包含 `title`、`date`、`pubDatetime`、`draft` 等属性）；
- **书籍模型输出（`BookDocument`）**：由适配器转换输出，每个条目的 `collection` 被显式标记为 `life` 或 `blog`，正文格式设为 `markdown`，`metadata` 保持对原始 `data` 的浅引用；
- **经典目录条目（`CatalogEntry`）**：轻量级展示结构，包含 `{ title, href, date, compactDate, narrowHidden }`，日期统一固定为 UTC 展示，避免服务端与客户端时区偏差。

Site 只开放 `@myblog/site` 一个导入路径。`buildHomepageModel()` 组合文稿适配、Book Build、主题挂接和页面样式；Tooling 用同一入口的 `inspectHomepageConfig()` 读取传统配置 Schema 与校验结果。书壳、浏览器启动、vendor 资源和光标由 Site 组件管理，不由 Book Build 或 Runtime 提供 Astro 子路径。

## 关键流程

站点全流程生命周期包含构建期装配、静态页面生成以及维护期格言更新两条主要链路：

```text
[构建期静态生成流水线]
触发 npm run build
   |
   v
加载生活与技术文章集合 + 读取并校验 book-config.json
   |-- 校验失败 ----> [立即终止构建，输出错误路径]
   |
   v
执行草稿过滤与发布日期合法性断言
   |-- 日期非法 ----> [立即终止构建，抛出异常报告具体文章 ID]
   |
   v
构建标准 BookDocument 并执行确定性倒序排序
   |
   v
驱动 Book Build 编译 Markdown、派生主题 CSS，生成 BookShell DOM
   |
   v
Astro 静态页面打包输出 (输出 / 翻页首页、/classic 经典页与单篇详情页)

-------------------------------------------------------------------------
[维护期每日一句同步链路]
触发每日一句更新脚本 (packages/site/src/cli/update-daily-quote.mjs)
   |
   v
向扇贝 API 发送 HTTP 请求并启动 5 秒超时保护
   |-- 请求成功且数据合法 ----> 格式化为标准格言对象返回
   |-- 请求失败或超时 --------> 尝试向有道 API 发起备用请求
                                   |-- 成功 ----> 格式化返回
                                   |-- 失败 ----> 回退使用 previous 历史快照
```

书籍适配器在非草稿日期非法时终止该转换；其他页面仍依赖自身前置政策。句子更新与页面构建分离，因此构建不直接依赖上游请求；配置或本地快照读取失败仍可能阻断构建。

## 设计取舍

### 封面预览与素材所有权

`start` 既用于折角预览，也用于实际翻页，不能据此判断书已打开。闭合状态只在 `turning` 提交目标页后解除，动画空闲后按当前物理页恢复。鼠标离开且没有提交翻页、没有活动拖拽时，适配器调用公开 `peel(false, false)` 取消预览；不停止实际翻页，不修改插件内部字典。

闭合状态不能代替运动状态：封面打开或合上时，`autoCenter` 会在双页画板与单页位置之间移动容器。若旋转封面背后仍绘制整页底衬，就会显露另一块不动的矩形，形成虚封页。

- 前封面的物理面为 1、2，后封面为 `totalPages - 1`、`totalPages`；末页号取自实际分页，不使用估算常量。
- `turning` 按当前视图和目标方向标记将运动的封面；`start` 按插件传入的物理页补充标记，包含未提交的预览。
- `book-cover-moving-front/back` 分别隐藏运动侧底衬和厚度装饰，不隐藏插件管理的真实封面，也不关闭另一侧的内页衬边。
- 插件仍报告运动时保留标记；空闲后先恢复端点状态，再清除运动标记。不能仅在 `turned` 回调到达时解除隐藏。

这项处理只管理装饰绘制，不插入中间跳页，不重启或重复触发翻页动画。键盘和鼠标的开、合操作分别检查每帧装饰状态、一次目标提交以及结束后的状态复原。

相邻正文页运动时，封二和封底内侧并不运动，但插件会将这些固定页包裹层降到 `z-index: -1`。书籍容器使用 `isolation: isolate` 将负层级限定在书籍内部，避免内封页落到外部页面背景之后。底衬宿主保持透明，仅通过裁剪伪元素绘制衬边，不能以整页实色覆盖固定页。两项约束同时成立，才能保留内封页表面；不以提高所有固定页的层级来绕过插件的运动排序。

Site 配置分别定义封二 `frontInside`、扉页 `titlePage` 和封底内侧 `backInside`。三者采用同一 `backgroundSize` 坐标尺度，不能依赖 vendor 的旧 `.p3` 原尺寸定位。扉页使用插画表面，不叠加通用纸纹；正文及出版说明保留纸纹。Build Schema 接受可选 `titlePage`，缺省兼容采用 `backInside`；当前 Site 显式指定不同切片。

出版说明节点被插件移出 DOM 后仍由插件缓存持有，返回范围时由插件重新挂载。Site 不以 `isConnected=false` 判断缺页，也不重新添加已登记的节点。验收应检查返回后的内容、尺寸和实际遮挡，不能只检查插件页码。

1. **集中式内容源适配器 vs. 散落在各页面组件**：我们选择在 `packages/site/src/internal/sources/` 建立单一权威适配器，虽然在数据传递上增加了一道显式转换，集中书籍模型政策；传统目录函数不自行过滤草稿，页面仍需负责可见性。
2. **静态构建期固化格言 vs. 客户端实时请求**：实时请求引入外部连通性、CORS 与等待成本。本地快照让页面构建可离线消费，代价是内容可能过期，更新失败返回 previous 而不保证当天句子。
3. **物理集中 Astro 源码于 `packages/site/src`**：路由、布局与组件由 Site 包统一持有；`astro.config.mjs` 将 Astro 的 `srcDir` 指向该目录，避免根级存在第二套应用源码。

## 失败与边界

在日常开发与持续集成中，需关注以下异常与边界处理：

1. **文稿日期异常熔断**：若文稿缺少有效日期且未标记为草稿，系统将抛出包含文稿文件名的错误，构建立即中止，杜绝未标注日期的乱序文稿上线；
2. **文章 ID 冲突风险**：若生活分类与技术分类存在相同文件名的文章，适配器目前按原样传递，在后续生成深链接哈希时可能引发定位冲突，写作时应保持 slug 唯一；
3. **每日一句接口全灭降级**：若两级第三方 API 均不可达且本地历史快照为空，fetchDailyQuote 记录上游失败并原样返回 previous，不校验该回退值；快照缺失时的写入和显示由调用方负责。

## 验证与演进

现有测试证明具体输入的政策和产物约定：

- **公共 API 契约测试**：`tests/integration/public-api.test.mjs` 覆盖草稿优先过滤、非法日期强拦截、时间戳稳定倒序及原数组不可变性；
- **配置与数据投影测试**：`packages/site/tests/homepage-config.test.mjs` 与 `packages/site/tests/homepage-data.test.mjs` 验证 Schema 约束与目录紧凑日期投影；
- **渲染集成与布局测试**：`tests/integration/homepage-render.test.mjs` 验证静态产物中 DOM 结构的完备性，`tests/e2e/homepage-layout.spec.mjs` 在无头浏览器中回归经典视图的流式响应表现。

未来演进规划：若后续引入多语言文章体系或新型归档分类，优先在 `packages/site/src/internal/catalog/` 扩展投影算子，保持底层内容模型与通用排版契约的稳定性。
