# 文档质量整改计划与证据

## 范围

落实文档审查中的 P0—P2：安全恢复、发布契约、架构事实、路径迁移、教程分类、质量追踪、元数据和技术语言。允许调整文档检查及其测试；用户追加授权后修复已复现的源码缺陷，不扩展新业务能力，不提交、推送或部署，不改历史原文。

- [x] 增强检查：先在 test/document-contract.test.mjs 添加教程、危险命令及过时路径回归并确认失败，再修改 scripts/engineering/internal/documents.mjs；执行示例、局部测试、check:docs、verify 和浏览器回归，记录真实结果。

源码与文档冲突按需求和已确认契约判断：修复 Publishing 工厂未配置 token 时的鉴权绕过；修复 Runtime 缓存重入结果、reset 的旧映射/样式、测量节点异常清理和预算耗尽静默截断。全部先新增失败回归，再最小修复，同步源码注释、API、设计和测试，不新增分布式队列或插件多实例能力。

上述步骤在当前工作区实施；已有改动必须保留，不使用整仓恢复。自动化新增规则只覆盖可确定的结构和危险模式，不声称验证设计正确性。
