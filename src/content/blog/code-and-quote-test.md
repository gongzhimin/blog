# 代码与引用的排版测试

## 行内代码

在正文中插入行内代码是一种常见的写作模式。比如你可以提到 `console.log("hello world")` 或者 `git commit -m "fix bug"`。行内代码通常使用等宽字体，并且有浅色的背景色来和正文区分。在 `JavaScript` 中，`const` 和 `let` 是声明变量的关键字。

## 围栏代码块

下面是一个简单的 JavaScript 函数：

```javascript
function fibonacci(n) {
  if (n <= 1) return n;
  let a = 0, b = 1;
  for (let i = 2; i <= n; i++) {
    const temp = a + b;
    a = b;
    b = temp;
  }
  return b;
}

console.log(fibonacci(10)); // 输出 55
```

代码块是最容易触发跨页拆分的元素。当一段代码超过当前页的剩余空间时，排版引擎应该能够在换行符处断开代码块，将前半部分放在当前页，后半部分移到下一页。拆分后的两个部分都应该保持正确的 `<pre>` 标签包裹。

## 多行引用

> 一个好的排版系统应该像空气一样——读者完全感受不到它的存在，但它却在默默地支撑着整个阅读体验。
>
> 当排版出现问题时——比如行距过密、字体过小、或者页边距不合理——读者可能说不出具体哪里不对，但他们会感到阅读变得费力。这种潜在的认知负担会降低信息传递的效率。

## 引用的跨页处理

如果引用块太长，它应该在行边界处被拆分。拆分后的两个部分各自保持 `<blockquote>` 标签的正确包裹。第一页的引用以省略号或自然断句结束，第二页的引用从新的句子开始。
