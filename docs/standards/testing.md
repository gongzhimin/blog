## 目的与范围

本规范约束六个 workspace 包、跨包集成、浏览器交互和交付门禁。目标是发现契约违例、数据丢失、未授权副作用和无法恢复的状态，不以测试数量代替证据。

默认测试不得读取生产凭据、调用真实发布接口或执行服务器恢复命令。真实环境验收需要明确目标、授权和恢复方案。

## 规则与要求

### 风险级别与强制证据

| 级别 | 典型风险                               | 最少证据                                               | 阻断条件                           |
| ---- | -------------------------------------- | ------------------------------------------------------ | ---------------------------------- |
| P0   | 未授权写入、内容删除、凭据泄露         | 合法对照、拒绝路径、外部调用次数、写入前后状态         | 任一违例或必要判据未验证           |
| P1   | 正文丢失、导航错误、错误契约、状态污染 | 正常、边界、失败、失败后恢复；涉及布局时追加真实浏览器 | 任一违例；仅静态断言替代行为       |
| P2   | 排版、导航便利性、维护成本             | 可观察结果或独立人工任务记录                           | 受影响要求未验收且没有明确延期决定 |

风险级别不改变退出码规则。范围内的任何失败都阻断本轮验收。已知源码违反已确认契约时必须修源码，不得通过删除断言、扩大容差或补写“限制”接受错误。

### 发现与防漏跑

- 模块测试：`packages/<name>/tests/**/*.test.mjs` 或 `*.test.cjs`。夹具归本模块；调用其他包的私有实现或读取另一包的配置实例属于集成测试。
- 集成测试：`tests/integration/**/*.test.mjs` 或 `*.test.cjs`。读取 `dist/` 前必须完成本轮构建。
- 浏览器测试：`tests/e2e/*.spec.mjs`。辅助文件放在 `support/`；当前 Playwright 只发现顶层 spec，嵌套 spec 必须被拒绝，不能静默漏跑。
- 每个实际测试文件登记到 `packages/tooling/src/modules.json`。递归盘点必须检查未登记、登记但不存在、不支持的路径或扩展名，以及空测试层。
- 禁止 `only`、`skip`、`todo`、`fixme` 和预期失败标记。需要延期的工作写入风险记录，不伪装成通过的测试。
- Node 运行结果必须包含非空测试计数，且 fail、cancelled、skipped、todo 均为零。静态检查不代替运行结果检查。
- 浏览器本地与 CI 均为零重试，禁止 only；运行报告门禁拒绝跳过、预期失败、重试及空集，不稳定测试不能凭重试后的绿灯验收。
- ESLint 警告上限为零；Astro check 的 error、warning、hint 都阻断验收。第三方终端提示另行核对，不把业务诊断降级来消除失败。

### 每个用例必须定义的内容

方案中的每项重要要求必须记录：

```text
要求 ID / 风险
  -> 环境、初始状态、输入或故障注入
  -> 调用与可观察结果
  -> 独立判据：具体字段、值、顺序、次数或上限
  -> 命名用例、责任包、测试层
  -> 当前覆盖限制
```

独立判据来自接口契约、人工构造期望或不变量，不能由被测函数生成 expected。负例必须有合法对照，防止“拒绝所有输入”通过测试。

每个公开任务入口至少覆盖：

1. 最小合法输入及输出字段、类型、顺序和默认值。
2. 空集合、单项、重复项、边界值和非法类型；不适用的项说明理由。
3. 配置缺失与覆盖、输入是否修改、共享引用条件。
4. 失败的诊断字段或异常类型；异常是否吞掉、传播或转换。
5. 有状态任务的首次调用、重复调用、失败中断、恢复与清理。
6. 有副作用任务的调用顺序、次数及禁止调用的边界。

公开类型声明必须纳入编译，不能用 skipLibCheck 隐藏本项目声明错误。编译夹具同时包含合法调用和非法参数（@ts-expect-error）；错误标记变为未使用时必须失败，防止接口悄悄退化成 any。该夹具不执行运行副作用。

新增输出字段、错误分支、可配置参数和状态转移必须同步增加对应断言。仅检查 `ok` 或返回码不合格。

### 分层与独立判据

| 层              | 能证明                                   | 不能证明                        |
| --------------- | ---------------------------------------- | ------------------------------- |
| Node / 请求替身 | 数据转换、错误传播、外部请求计划         | 真实 GitHub 权限、提交、代理    |
| 回环 HTTP       | 方法、路径、解析、鉴权、响应、实例内排队 | TLS、跨进程锁、持久队列         |
| JSDOM           | DOM 结构、属性、状态、清理               | 字体布局、真实高度              |
| 构建产物        | 标记、载荷、资源引用与顺序               | 加载后交互和可见性              |
| Chromium/WebKit | 指定资源与视口的布局和交互               | 实际 Safari、真机触摸、所有字体 |
| 工程扫描        | 有限语法和结构规则                       | 所有动态代码、文档语义          |
| 人工阅读任务    | 读者能完成指定任务                       | 未走查文档或其他读者群体        |

分页必须分别断言文本完整性、顺序、行内属性、导航和高度。高度使用独立 DOM 容器，不复用被测测量助手；明确 CSS、宽高、字体条件和容差。不可分割元素的溢出策略另测，不能用普通段落案例证明图片、表格或代码块。

浏览器共享 fixture 捕获未处理异常、同源 HTTP 错误和同源资源加载失败。故意注入这些故障时需要独立负例测试，不能向通用 fixture 加宽泛忽略规则。

### 异步、隔离与资源

- 等待条件、事件或受控 Promise；不得用固定 sleep 判断初始化完成。
- 并发测试用屏障控制首任务，验证后续任务在释放前没有进入受保护阶段；失败后队列仍可继续。
- 网络、时间和随机值通过替身或固定夹具控制。不得依赖生产状态。
- 回环 HTTP 使用随机可用端口；server、计时器、DOM、全局配置和临时目录必须 teardown。
- Node 单文件运行上限 30 秒，浏览器单用例上限 60 秒。它们用于终止测试，不证明产品具有相同超时保证。
- 日志和附件不得包含 token、私钥或生产正文。截图不替代断言。

### 门禁自身也必须测试

扫描器至少有合法对照和违规注入：在真实包目录放入非法依赖、坏文档或未登记测试，检查指定检查确实失败。扫描空的旧目录、执行空测试集或只断言检查函数存在都不合格。

测试文件递归盘点与执行发现必须一致；修改测试发现、模块清单、报告解析和工作流时必须保留相应正反例。

## 执行流程

1. 列出受影响契约、风险及状态转移，选择模块、集成和浏览器证据。
2. 修复行为前先运行失败回归，确认失败来自目标缺陷，不是语法或环境故障。
3. 最小修复后运行失败回归与合法对照，核对异常路径和资源清理。
4. 执行 `npm run verify`；浏览器行为变化及交付候选执行 `npm run verify:release`。
5. 核对机器结果和未执行阶段，记录命令、环境、产物来源、退出码及覆盖限制。
6. 文档、接口、测试方案同步修改；阅读任务另行记录，不由标题检查代替。

## 正反例

- 合格：正文拼接等于原文，分片属性保持，独立测量不超出声明容差。
- 合格：错误 token 返回 403，GitHub 替身调用数为零；合法 token 对照完成一次提交计划。
- 合格：首次目录 1 页、随后 2 页时，链接、双向映射和实际正文起页一致。
- 不合格：只检查 pages 非空、HTTP 有响应、截图已保存或命令退出零。
- 不合格：删除失败案例、使用旧 dist、重试直到通过、忽略所有资源错误。
- 不合格：调用被测转换函数生成预期结果，或把模拟器的高度当成真实排版证据。

## 例外与限制

没有测量基线时不得编造性能、可用率或覆盖率阈值。当前不采用任意覆盖率百分比：先按风险列出遗漏分支，再补确定性案例；覆盖率只能帮助定位遗漏，不能证明判据有效。

未实现的安全或设备能力必须记录责任、风险、临时控制及补齐触发条件。延期决定不允许将失败测试标为通过，不允许自动发布。真实部署、恢复演练和外部服务故障验证均需另外授权。

静态检测有语法边界。动态创建测试标记仍需运行结果兜底；浏览器报告器按实际 expectedStatus、status 和 retry 拒绝跳过与预期失败。不声称 AST 识别所有表达式，审查仍需核对判据。

## 检查与验收

```sh
npm run check:tests
npm run verify
npm run verify:release
```

- `check:tests` 是文件盘点和标记检查，不执行测试。
- `verify` 短路执行格式、lint、契约类型、文档、依赖、测试策略、Astro、构建和 Node。
- `verify:release` 在 verify 后执行 Chromium/WebKit；`test:e2e` 生命周期先盘点并重新构建，禁止复用已有 preview。开发服务默认 4321，测试 preview 固定 4392；端口冲突须报告，不能自动停止无关进程。CI 安装两个引擎，不允许缺失引擎时降为单引擎通过。
- 必须零失败、零取消、零跳过、零 TODO、零重试，并且测试集非空。
- 前序失败后的阶段标为未执行，不能引用历史结果。
- 有 P0/P1 契约违例、漏跑或缺失关键判据时不验收。机器通过仍需核对人工要求与覆盖限制。
