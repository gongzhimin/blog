## 问题与目标

### 演进原则

改造由变化压力驱动，不由目录美观驱动。先判断责任、调用者、状态、权限和生命周期，再选择拆文件、接口、包或服务。移动文件只能改变位置，不能证明解耦。

迁移顺序：明确责任与 API、建立失败证据、改变内部责任、迁移全部消费者、删除旧入口、验证交付。序列化或命令变化需同步调用方、部署清单与恢复方法；不保留 redirect 或内部实现转发。

## 范围与约束

本文是演进准入与风险台账，不把建议当作已实现功能。当前六个私有 workspace 包共享根安装与锁文件、分别登记版本和 exports；Astro `srcDir` 为 `packages/site/src`，浏览器 Runtime 源由 Vite 打包。包根 API 只提供各自的常见任务，宿主资源子路径按各包 API 参考说明。

提出拆分时必须提供真实消费者、状态或权限压力以及验证收益，不能仅凭目录行数决定。

迁移不自动授权线上部署、公开投稿、多租户或新的凭据范围；这些变化需要独立需求和安全评估。

## 系统上下文

- 演进压力来自四处：作者增加输入格式或多人发布；
- 读者增加设备与字体差异；
- 维护者需要更安全的上线恢复；
- 独立消费者希望复用书籍构建或阅读器。当前静态个人博客不要求每个模块独立扩缩容。完整上下文见 [总览](overview.md)，新压力出现时先修改质量场景，再调整模块边界。

## 模块与依赖

### 是否继续解耦

六个 workspace 包的物理边界已经建立；是否继续拆分应看真实消费者、状态所有权和独立版本压力，不因目录数量增加而拆包或拆服务。

Publishing 已隔离输入转换、GitHub transport 与 HTTP 生命周期。包根 `startServer()` 显式启动 listener；导入不监听。不得从其他包导入 Publishing 内部实现。

后续权限或并发需求应通过 API 契约和外部写入证据验收，不能只增加文件。

Runtime 在多实例或复用压力出现时，应把配置、缓存、测量 DOM、插件生命周期显式化，降低全局单例耦合。为了包化改脚本加载会影响 URL、插件及页面结构，需要独立基线。

Site 位于 `packages/site/`，包含框架路由、组件、布局、样式、内容与数据；公开首页组合入口为 `buildHomepageModel(input)`。新内容源先适配模块模型，不向 renderer 注入集合选择。

### 拆包与分服务准入

独立消费者、版本周期、强制 exports 封装或安装压力出现时重评 workspaces。需要 API 稳定、单向依赖、独立契约测试、可迁移路径与成本依据。

分服务需要不同权限、扩缩容、故障隔离或生命周期的证据，还需承担网络协议、部署协调和观测成本。“已经分文件夹”不是理由。

当前决定见 [ADR 0004](../decisions/0004-physical-modules-and-public-api.md)。

## 数据与契约

拆分必须保持 BookDocument 的来源无关性和 HTML/JSON 载荷的可追踪性。若文章 key 改为强唯一标识，应设计旧 ?post 链接迁移；若配置从 JSON 数据扩展为行为对象，不能继续依赖 JSON clone 语义。

Runtime 多实例需要实例级配置、测量节点、缓存及销毁职责，不能只在全局对象上增加参数。

这些是重设计触发条件，不是当前能力。现行契约见 [运行契约](../reference/book-runtime-contract.md)。

## 运行与部署

Webhook 工作流按 `packages/**` 触发，部署完整 workspace 目录和根 manifest/锁文件，以保证 npm 能解析本地工作区；服务由 `packages/publishing/src/cli/publish.cjs` 启动，健康检查入口为 `packages/operations/src/cli/health.cjs`。

Runtime 由 Assets.astro 引入 browser-entry，经 Vite 打包；API 模块先初始化再启动 app。后续修改继续同步上传清单、资源组合、测试与依赖安装，防止本地完整而服务器缺实现。

站点与 webhook 两条工作流共享 main、锁文件和服务器，不是原子发布。跨两者协议变更先设计新旧版本并存及回退；引入 release 目录或原子链接切换属于后续交付改造，当前仍是覆盖同步。

现行时序见 [运行视图](runtime-and-deployment.md)。

## 设计取舍

workspace 包边界已落地；继续拆分优先考虑模块内部责任与副作用所有权。跨包调用限制在任务 API 和登记的宿主资源入口，Tooling 门禁检查依赖方向；不据此推断各包可以独立部署或发布。

workspace 包独立版本与共享锁文件同时存在；变更版本前需核对消费者范围及打包结果。`private: true` 表示当前不发布到 registry。

Runtime 实例化可隔离缓存和生命周期，却必须定义 mount/destroy、DOM 所有权及资源就绪；不能把全局脚本机械换成 ES module 就称已解决。高可用或独立服务会增加网络失败与观测成本，不为个人站点提前引入。

## 风险与验证

### 风险台账

| 编号/优先 | 事实及影响                                          | 控制                         | 再评估触发             |
| --------- | --------------------------------------------------- | ---------------------------- | ---------------------- |
| R1/高     | 发布大小/速率限额有缺口，转换/transport/HTTP 已分离 | token、转换测试、非强制引用  | 多人或输入量增长       |
| R2/高     | HTML 受信，未建立不受信内容安全                     | 限定作者资产、人工审查       | 外部抓取或公开投稿     |
| R3/高     | rsync 混合文件风险，工作流非事务                    | 验证产物、失败停止、健康检查 | 跨站点/服务兼容变更    |
| R4/中     | 分页受资源状态影响，终端覆盖有限                    | Chromium 测量与交互          | 新主题/字体/iOS 差异   |
| R5/中     | 类型限定范围，动态配置较宽                          | Schema、校验、接口审查       | 结构扩展或反复字段错误 |
| R6/中     | 静态入口有 import 顺序，全局 DOM/配置仍单例         | 顺序测试和 adapter           | 多实例或库复用         |
| R7/中     | 静态门禁不证明语义/运行隔离                         | 人工设计及事实审查           | 绕过或文档漂移         |
| R8/中     | 健康只覆盖基础链路                                  | 分项结果和内容核对           | 自动新版验收           |
| R9/中     | 有限哈希 key、估页和日期环境假设                    | 明确契约及测试               | 大内容集或跨时区要求   |

台账来自本地审阅，不是生产安全审计。没有证据不能声称线上故障或已经消除风险。

### 从风险进入任务

触发风险后写限范围设计，说明场景、非目标、替代、兼容和验收。本文建议不是实现授权。内容丢失、越权和恢复失败优先于一般美化。

完成后更新事实与措施，不删除仍有效的局限；选择改变写新 ADR 替代旧决定。改善需有基线与方法，文件数、行数和测试数不能替代质量判断。
