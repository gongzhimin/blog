# 博客 UI 设计规范

## 背景

这是一个以写作为核心的个人博客，内容分为两类：生活随笔（Essays）和技术文章（Technical）。当前站点已经具备稳定的内容发布与部署链路，接下来重点应放在页面气质、阅读秩序和视觉一致性上，而不是扩展页面数量或引入复杂交互。

## 目标

1. 建立统一的编辑风格，让站点看起来像一份经过认真排版的个人文集。
2. 明确每类页面的职责，避免首页、归档页、详情页互相抢夺视觉重点。
3. 强化阅读体验，保证正文、标题、引用、代码块、图片和标签在视觉上稳定一致。
4. 保持克制，不引入过重的卡片化、插画化或商业化信息架构。

## 范围

本规范覆盖以下 5 类页面：

1. 首页
2. 栏目归档页
3. 文章详情页
4. About 页
5. RSS / Feed

不在本次规范中的内容：

1. 分页系统的重构
2. 搜索系统
3. 标签聚合页
4. 评论系统替换
5. 多主题切换

## 设计原则

### 1. 编辑感优先

页面应呈现“目录 + 正文”的阅读秩序，而不是“营销首页 + 功能面板”的结构。站点气质以克制、安静、可长期阅读为主。

### 2. 统一的内容宽度

所有页面采用统一的内容宽度体系：

- 首页采用较宽容器，承载双栏目录
- 归档页和文章页采用窄一些的阅读容器
- About 页采用最紧凑的个人介绍容器

### 3. 视觉层级清晰

每个页面只允许一个主焦点：

- 首页的主焦点是栏目入口
- 归档页的主焦点是文章列表
- 文章页的主焦点是正文
- About 页的主焦点是作者身份

### 4. 克制的装饰

保留纸感背景、细边线、衬线字体、轻动效和少量标签装饰。避免大面积阴影、强烈渐变、复杂卡片和过多分隔模块。

### 5. 统一的功能文本

日期、栏目名、返回链接、RSS、标签等功能信息统一使用更小的字号、更轻的字重和更冷静的颜色。

## 页面规范

### 首页

首页的职责是建立第一印象，并为读者提供两个稳定的入口：Essays 和 Technical。

页面内容应包含：

- 站名或作者名
- 一句短介绍
- 两个栏目分区
- 每个栏目下最新若干篇文章
- About 和 RSS 的简短入口

首页不应包含：

- 大段摘要
- 过多文章卡片
- 复杂视觉主图
- 任何干扰栏目入口的次级模块

视觉要求：

- 双栏结构在桌面端成立，在移动端自动坍缩为单栏
- 栏目标题保持统一的功能文本风格
- 文章标题比栏目标题更醒目，但不应接近详情页标题的强度
- 每个栏目下的列表应具备稳定的行距和分隔线节奏

### 栏目归档页

归档页的职责是快速浏览文章，并提供稳定的日期顺序。

页面内容应包含：

- 栏目标题
- 简短说明
- 按时间倒序排列的文章列表
- 每条记录的标题与日期

归档页不应包含：

- 过强的封面感
- 首页式的宣传语
- 额外装饰模块

视觉要求：

- 标题、日期采用左右分栏或上下层级的稳定排版
- 列表项之间使用细分隔线
- 日期使用较小字号和中性色
- 文章标题应保持可扫读，不要过于花哨

### 文章详情页

文章详情页的职责是阅读。正文必须始终是页面中心。

页面内容应包含：

- 返回链接
- 日期
- 主标题
- 可选摘要
- 标签
- 正文
- 评论区

文章详情页不应包含：

- 复杂导航
- 多余侧栏
- 和正文争抢注意力的大面积装饰

视觉要求：

- 标题层级明显高于正文
- 正文宽度应控制在适合连续阅读的范围内
- 段落、引用、列表、表格、代码块和图片都要有统一的排版规则
- 文章正文中如果存在重复的首个 Markdown 标题，应避免与页面布局标题重复显示
- 生活随笔允许使用首字下沉，但技术文章不使用首字下沉

### About 页

About 页的职责是建立作者身份感，并提供最小必要的联系信息。

页面内容应包含：

- 作者名
- 身份说明
- 简短自述
- 社交链接

About 页不应包含：

- 大段履历
- 复杂分组
- 冗余说明

视觉要求：

- 头像或标识与文字信息形成稳定的左对齐结构
- 社交链接应以小型按钮形态呈现
- 页面整体应比首页更安静、更轻

### RSS / Feed

RSS 是基础设施，不做额外视觉设计。

要求：

- 输出最新文章
- 保持标题、链接、发布时间和描述正确
- 与站点主内容保持一致

## 视觉规范

### 色彩

- 背景使用暖色纸感底色
- 主文本使用柔和深色，不使用纯黑
- 辅助信息使用更浅的中性色
- 分隔线使用低对比度细线
- 标签和按钮只允许少量强调色

### 字体

- 正文使用衬线字体，形成稳定的阅读气质
- 功能文本使用无衬线字体，增强信息层级
- 标题与正文保持同一字体系统，不引入额外字体

### 间距

- 页面顶部和模块之间保留明显留白
- 列表项之间保持均匀节奏
- 详情页正文段落之间留出舒适的阅读距离
- 任何模块都不应挤压到“显得拥挤”的状态

### 边框与阴影

- 以细边框为主
- 阴影仅用于极少数视觉强调场景
- 不使用厚重卡片和强浮雕效果

### 动效

- 只保留轻量首屏淡入
- 列表项允许轻微序列出现
- 不增加阻塞阅读的复杂动效

## 组件规范

### 品牌区

职责：提供站点识别。

组成：

- Logo
- 站名

### 栏目标题

职责：标识内容类型。

规则：

- 统一为小号功能文本
- 使用细分隔线
- 与栏目内容保持足够间距

### 列表行

职责：承载标题和日期。

规则：

- 标题为主信息
- 日期为辅信息
- 每条记录之间用细线隔开

### 文章头部

职责：建立阅读起点。

组成：

- 日期
- 主标题
- 摘要
- 标签

### 正文内容

职责：承载长文本阅读。

规则：

- H1、H2、H3 的层级要稳定
- 引用、代码、表格、图片都有固定样式
- 图片必须保持可读和不突兀

### About 卡片

职责：表达作者身份。

组成：

- 头像
- 作者名
- 身份说明
- 社交链接

## 响应式规则

### 桌面端

- 首页采用双栏目录结构
- 归档页和详情页使用窄内容宽度
- About 页保持紧凑

### 移动端

- 首页双栏自动变为单栏
- 归档列表每条记录允许上下堆叠
- 文章标题和正文缩小到适合单手阅读
- About 页头像与文字改为纵向堆叠

## 可接受的实现方式

本规范允许通过以下方式落地：

- 全局 CSS 定义页面壳和排版系统
- 页面层使用少量语义化 class
- 详情页通过布局组件统一标题、摘要和标签
- 首页与归档页保留静态生成模式

不建议的实现方式：

- 在每个页面上继续堆大量 inline style
- 为每个页面单独发明一套视觉语言
- 把首页做成内容杂烩页

## 验收标准

以下情况视为符合本规范：

1. 首页能清楚区分 Essays 和 Technical 两个入口。
2. 归档页可以快速扫读文章标题与日期。
3. 文章详情页的正文是唯一阅读中心。
4. About 页具备明确的作者身份感。
5. RSS 输出正确，没有额外视觉负担。
6. 页面在桌面和移动端都保持稳定、自然的排版。
7. 整站不再依赖大量 inline style 维持视觉秩序。

## 风险与约束

- 文章数量增长后，归档页和首页列表仍然会变长，但这属于信息量增长，不属于 UI 失效。
- 如果后续继续增加复杂功能，页面职责需要重新审视，避免首页再次变成信息堆叠页。
- 本规范优先强调一致性和可读性，不追求强视觉实验。
