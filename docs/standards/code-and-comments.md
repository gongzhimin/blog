## 目的与范围

约束自研 JavaScript、TypeScript、Astro、Shell 及源码注释，审查责任、输入输出、错误处理和资源所有权。
核心目标包括：

1. 保证代码的单一职责与局部可理解性，使维护者在修改具体功能时无需臆测跨模块隐式依赖；
2. 规范源码注释的职能边界，注释用于记录无法从语法树直接推断的设计意图、不变量约束与维护边界，杜绝无意义的语法复述；
3. 统一异步调用、异常处理与资源生命周期的设计准则。

本规范约束全代码库的日常开发与重构，排除历史归档文件（`docs/archive/`）与只读第三方上游原件（`turnjs4/`、`public/vendor/`）。

## 规则与要求

### 1. 模块组织与单一职责

代码文件的划分必须严格围绕“单一变化原因”组织，行数仅作为审查的辅助信号而非机械的拆分标准。当一个文件同时出现以下三种信号时，必须实施职责拆分：

- 混杂了不同的生命周期（如将无状态的数据格式转换与有状态的 HTTP 服务器监听写在同一模块）；
- 编写单测时必须模拟大量与核心功能完全无关的外部环境（如测试纯文本算法却被迫 mock 网络客户端）；
- 外部调用者必须深入了解内部多步实现顺序才能正确调用。

跨模块调用一律限制在 `packages/tooling/src/modules.json` 清单显式登记的 `api/` 入口，严禁私自越权导入其他模块的内部文件。

- 六个模块实现均在 `src/`，每个模块自行管理 `api/`、私有实现、`tests/` 和文档；命令行入口放所属模块 `cli/`，只负责进程输入、显式调用和退出。
- `owns` 只能是模块根路径；不能用 applicationEntries 或工具名认领其他目录。公开 API 不能因放进 cli 或 tools 而被绕开。
- 仅一个模块使用的开发工具随模块管理；仓库门禁及工程配置归 Engineering。不新增根 scripts/tools 或转发入口来规避归属。
- 根新增文件或目录须说明为何不能归入现有责任范围，并同步结构验收；生成物和依赖目录不按源码模块登记。

### 2. 契约定义与类型表达

所有跨模块公共 API 必须使用标准化 JSDoc 显式标注输入参数、返回值模型、抛出异常以及可能的副作用。

复杂数据模型优先通过 `@typedef` 引用规范类型定义文件（如 `packages/book-build/src/api/types.mjs`），严禁未经验证的外部数据以模糊的 `any` 或 `object` 穿透多层模块边界。
输入校验在最早掌握完整语义的边界执行：简单字段使用明确类型和范围判断，复杂配置使用权威 JSON Schema，业务规则由所属模块校验。避免多处复制规则。认证配置缺失必须拒绝创建服务，不能让缺失值之间的相等比较构成授权。

### 3. 异步、状态与资源生命周期

在引入全局变量、内存缓存、DOM 测量容器、事件监听器或系统定时器时，必须在设计中明确回答五个问题：

- 资源由谁创建并分配内存？
- 资源由哪个上下文持有所有权？
- 缓存何时失效？是否支持多次重入调用？
- 异常退出时由谁负责确保资源被安全销毁？
- 是否可能引发内存泄漏或事件重复绑定？

- 异步调用必须由调用者 await 或明确处理失败；
- 后台任务声明错误接收者及取消责任。等待资源就绪使用事件、Promise 或可验证标记，不以固定延迟保证就绪。重试记录次数、间隔、停止条件和结果不确定时的处理；
- 本地队列不能称为分布式锁。

### 4. 异常安全与敏感信息脱敏

- catch 用于既定降级、错误映射或补充上下文；
- 不能静默吞错并返回成功。创建临时 DOM、连接或计时器后，使用 finally/teardown 保证异常清理。缓存命中返回值应保持首次成功的字段和含义；
- reset 清除本实例数据及导航映射，不影响其他实例资源。达到处理预算但仍有未消费输入时必须明确失败，不能返回截断内容作为成功。

在任何日志输出、控制台打印、报告生成或测试断言中，严禁打印明文 Token、SSH 私钥内容、全量 Base64 二进制字节或敏感文件全文。

### 5. 命名规范与源码注释边界

- **命名规范**：普通文件/目录采用 `kebab-case`，组件文件采用 `PascalCase`；函数/变量采用 `camelCase`，类型/类采用 `PascalCase`，固定常量采用 `UPPER_SNAKE_CASE`。参数不能从上下文判断单位时写明单位，如 `articleWidthPx`；局部明确的数组 `index` 不强制改名。已有公开字段改名需要契约迁移，不为排版统一单独破坏消费者；
- **注释内容分类准则**：
  - **JSDoc 注释**：阐述参数模型、边界约束、前置条件与抛错类型；
  - **不变量注释**：记录算法必须维持的物理条件（如“全书总页数必须为偶数”、“测量容器样式必须与展示样式盒模型绝对一致”）；
  - **决策背景注释**：记录为何选择某种非直觉实现（如“为避免并发覆盖历史，必须设置 force: false”）；
  - **严禁的低质量注释**：严禁仅复述语法的废话注释（如 `// 定义一个变量`、`// 循环遍历数组`）。

## 执行流程

实施代码编写与重构时的标准检查清单：

1. **修改前确认**：明确待改动逻辑所属的模块，确认调用方与受影响的契约测试；
2. **编写实现与类型**：补充准确的 JSDoc 注释，对于配置变更，更新单一权威 Schema 并执行自动生成；
3. **资源生命周期排查**：检查所有新增的定时器、DOM 节点、子进程是否在正常及异常路径下均具备对应的销毁清理逻辑；
4. **清理失效注释**：代码逻辑修改后，必须同步修改或删除与新逻辑不再一致的旧注释；
5. **门禁全量校验**：执行 `npm run verify`，确认 ESLint、Prettier、边界规则与全量自动化测试全部通过。

## 正反例

### 合格接口与注释示例

```js
/**
 * 将展示层正文页码换算为全书连续物理页码。
 * 目录页、封面与封底不属于正文页，不适用此转换。
 *
 * @param {number} displayPage 正文可见页码，从 1 开始递增的有效整数
 * @param {number} bodyStartPhysical 正文第一个页面的全书物理起始页号（通常为 5 + 目录占用页数）
 * @returns {number} 映射后的绝对物理页号，可直接交付给翻页阅读器
 * @throws {RangeError} 当任一参数不是正整数时抛出
 */
export function toPhysicalPage(displayPage, bodyStartPhysical) {
  if (
    ![displayPage, bodyStartPhysical].every(
      (val) => Number.isInteger(val) && val > 0,
    )
  ) {
    throw new RangeError(
      'displayPage and bodyStartPhysical must be positive integers',
    );
  }
  // 物理页号不变量：正文第 1 页严格等于物理起页，后续页码线性递增
  return bodyStartPhysical + displayPage - 1;
}
```

### 不合格典型反例

- **反例一：无意义的复述注释**：
  ```js
  // 调用函数获取配置
  const cfg = getConfig();
  ```
- **反例二：静默吞没异常的危险写法**：
  ```js
  try {
    applyConfig(cfg);
  } catch (e) {
    // 忽略错误，继续运行
    return true;
  }
  ```
- **反例三：未声明度量单位的混淆参数**：
  ```js
  function setDimensions(w, h) { ... } // 调用方无法得知是 px, rem, 还是百分比
  ```

## 例外与限制

1. **废弃入口**：迁移全部仓库消费者并删除旧入口，不建空壳转发或迁移占位文档。独立的启动 CLI 是应用入口，不是废弃接口兼容层；跨已部署版本的协议过渡需要明确授权、兼容矩阵和移除条件；
2. **第三方类库局部降级**：对于引入的第三方历史类库（如老旧 jQuery 插件 Turn.js），若其原生未提供标准的 TypeScript 类型或销毁接口，允许在其外围适配层中封装生命周期降级逻辑，但必须在适配层注释中详细注明其局限性，严禁让未受控的第三方状态污染核心模块。

## 检查与验收

代码合并前，人工审查与自动化门禁必须满足以下验收标准：

- [ ] 源码未发生跨模块未授权导入，符合 `packages/tooling/src/modules.json` 的边界定义；
- [ ] 所有导出的公共函数具备完整严密的 JSDoc 参数与异常标注；
- [ ] 状态与异步操作具备确切的取消、重试上限与资源清理保障；
- [ ] 自动化测试包含针对非法参数的防御性拦截用例；
- [ ] 执行自动化代码检查，确认零报警通过：
  ```sh
  npm run check:boundaries
  npm run verify
  ```
