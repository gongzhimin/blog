## 问题与目标

在博客与独立出版场景下，文章内容既可能来自站点静态集合（Astro Content Collections），也可能来自独立的 JSON 数据文件。

无论来源形式如何，在生成可翻阅的拟真书籍时，都需要经过统一的流程：渲染富文本 HTML、生成层级目录、应用几何尺寸并注入主题样式。

如果由每个业务页面各自进行上述拼装，来源追踪、首行标题剥离、目录罗马数字页码映射以及深链接哈希逻辑将迅速发生逻辑漂移；反之，若在构建层直接耦合站点特有的草稿状态和发布策略，则会导致通用的书籍排版引擎失去跨场景复用的能力。

- 为了解决上述问题，Book Build 模块引入了 `BookDocument` 作为规范化的输入内容模型，并对外输出统一的静态阅读载荷。本模块的设计目标是建立清晰的构建期不变量：保证各章节条目在组装过程中的相对顺序与全局身份可精确溯源；
- 确保文章正文 HTML 与书籍目录严格源自同一条目切片；
- 杜绝装配过程对原始传入配置对象的就地修改；
- 并让调用方明确区分“构建期预估页码”与“浏览器实测物理页码”的语义界限。

## 范围与约束

在系统的模块分工中，职责边界划分如下：

1. **站点模块（`packages/site`）**：负责内容资产的物理存储、草稿过滤策略、路由注册以及最终 Astro 页面的布局组装；
2. **Book Build（`packages/book-build`）**：负责来源无关的内容模型、Markdown 与公式渲染、书籍配置校验，以及将输入 CSS 转换成显示/测量样式；
3. **书本运行时（`packages/book-runtime`）**：在浏览器测量与拆分正文，返回实际物理页和文章映射；页面装配、导航与翻页交互归 Site。

为了维持模块自治性，本模块不直接导入运行时或站点的内部实现代码，所有跨模块的数据交付均严格通过序列化 JSON、静态 HTML 标记以及全局挂载的 `window.MEASURE_CSS` 完成。

输入的内容正文假定源于受信任的写作资产，模块内部不包含 XSS 过滤防护；由于构建期无法获知客户端真实的设备字体、高分屏缩放比例及动态网络图片加载耗时，因此构建期输出的初始页码仅作为冷启动占位材料。

## 内部组成

模块内部按照单一职责原则进行功能切分，核心组成如下图所示：

```text
Site Astro/JSON --适配--> BookDocument --输入--> api/index.mjs
             |-- 配置校验器 (validator) --> api/book-config.schema.json
             |-- 装配器 (assembler) -----> 驱动渲染回调并组装载荷
             |-- 主题工厂 (book-theme) -> 将输入 CSS 派生为显示 / 测量样式
             +-- 渲染管道 (renderer) ----> marked / KaTeX / highlight.js
                                             |
                                             +-> 本地图片尺寸探测(可选)

Site CSS (?raw) -> Book Build createBookTheme -> 显示 / 测量 CSS
Astro页面构建 -> Site BookShell.astro --> 输出 DOM 骨架 / 配置 / MEASURE_CSS
公共类型定义 -----------------------------> api/types.mjs
```

Site 的 Astro 页面负责渲染书壳、导入展示 CSS 与装载浏览器 Runtime；这些宿主资源不属于 Book Build。本包只消费模型、配置与显式传入的 CSS 字符串。

各内部子系统的核心职责说明：

- **来源边界**：Astro/JSON 适配器归 Site。Build 接收 `BookDocument`，不保留第二份来源适配器；来源转换及其类型、测试在 Site 维护。
- **核心装配器（`assembler/`）**：执行文章身份（`key`）计算、预估目录编排、配置深拷贝以及生成供书壳消费的数据对象；
- **正文渲染器（`renderers/`）**：封装 Markdown 词法分析、代码块语法高亮、数学公式渲染以及本地图片尺寸嗅探逻辑；
- **主题工厂（`themes/`）**：接收 CSS 字符串并按主题规则派生供运行时测量的 CSS；不负责定位或读取 CSS 文件。
- **书壳组件**：不由 Book Build 提供。DOM 骨架由 `packages/site/src/components/BookShell.astro` 拥有。

## 数据与接口

在数据结构层面，`BookEntry` 封装单篇章节的数据载荷，包含调用方应确保唯一的标识 `id`、归属集合 `collection`、章节标题 `title`、发布日期 `Date`、正文原始内容 `body` 以及格式枚举 `bodyType`（支持 markdown 或 html）。

`BookDocument` 则聚合整本书籍的顶层元信息（`id`、`title`、`tocTitle`）与有序的章节列表 `entries`。

- 文章有两套标识：数据源提供 `id`（如文件名或文章 slug），运行时使用由 CRC32 与 proquint 编码派生的导航 `key`。调用方必须保证章节 ID 唯一；
- 不同 ID 也可能产生相同 key，短哈希不提供无碰撞保证。key 用于客户端导航，不应替代源数据身份标识。本包生成阶段不检测碰撞；Runtime 在正文测量前拒绝重复非空 key，返回诊断，不交付歧义映射；
- 引入检测或调整编码时，须同时评审装配、目录和深度链接契约。

装配函数在执行时必须满足严格的数据不变量约束：

1. **顺序保真**：输入的 `entries` 顺序在经过装配后与输出的 `articles` 列表严格保持一一对应；
2. **配置隔离**：装配逻辑不得修改调用方传入的原始配置对象，内部统一执行深拷贝以确保配置对象引用隔离；
3. **渲染分支区分**：声明为 `html` 格式的条目直接跳过 Markdown 编译器，但统一经过一级标题去重剥离流程，防止与阅读器顶栏标题视觉重叠；
4. **预估页码语义**：目录默认从第 7 页起排，预估总页数采用线性启发式规则（$9 + 3n$），该数值仅供书壳初始化骨架使用，运行时将按真实测量结果覆写。

## 关键流程

书籍构建的核心生命周期涵盖从源数据转换到静态载荷输出的完整链路：

```text
源数据输入 -> 数据源适配器 ---- 日期或格式非法 ----> [抛出异常中断]
                   |
                   v
            BookDocument 实例就绪
                   |
书籍配置源 -> 显式调用配置校验器 -- 违反 Schema 契约 ----> [抛出异常中断]
                   |
                   v
              装配流水线执行
                   |-- 剥离文章首行重复标题
                   |-- HTML 条目直传 / Markdown 条目编译
                   |-- 计算短哈希 key 与初始目录索引
                   |-- 深拷贝书籍几何配置并注入来源元数据
                   |
                   v
标准阅读载荷 (articles/toc/config) 就绪
                   |
Site 的 CSS 字符串 -> createBookTheme ---- 未知主题标识 ---> [抛出异常中断]
                   |
                   v
      Site BookShell 输出 DOM + data-config + MEASURE_CSS
                   |
                   v
           [静态编译阶段交付完成]
                   |
            站点模块注入客户端运行时脚本 (Runtime Assets)
                   |
            浏览器端执行真实 DOM 排版与物理分页测量
```

在整个流程中，异常处理采取立即熔断策略：已抛出的数据源、显式配置校验或渲染回调异常直接传播，不返回部分载荷；Markdown 解析器通常容错，不能把普通语法差异都称为致命错误。

本地图片尺寸探测属于尽力而为（best-effort）操作，若图片路径不存在或无法解析，将安全保留原始图片标签而不中断构建。

## 设计取舍

1. **采用统一内容模型 vs. 允许数据源直通**：引入 `BookDocument` 规范模型增加了一层内存对象的转换开销，隔离了不同数据源（Astro 集合、外部 CMS、独立 JSON 文件）与排版装配器的依赖关系，避免了业务元数据渗透入底层排版逻辑。
2. **构建期预估页码 vs. 浏览器端真实测量**：在构建期无法精确预知不同客户端设备的屏幕像素密度、抗锯齿算法以及本地字体的物理排版高度。因此，我们选择在构建期仅计算占位预估页数，而将最终的物理折行与分页切片全权交给浏览器运行时执行。
3. **样式转换与宿主 DOM 分离**：Book Build 只从 CSS 字符串生成显示/测量样式；Site 拥有 `BookShell.astro` 并决定 DOM、资源与 Runtime 脚本顺序。这样 Book Build 可在 Node 环境复用，不需要依赖 Astro。
4. **通过规则派生测量样式 vs. 维护双份样式文件**：测量样式与展示样式的盒模型必须严格对齐。我们选择基于显示样式文件通过正则规则动态提取并转换选择器，减少手工同步成本；正则转换支持的选择器有限，源码字符串一致不保证最终盒模型等价。

## 失败与边界

在系统运行与交互过程中，可能出现如下异常边界与故障场景：

1. **配置校验失败**：如果配置对象缺失必填属性或数值越界，`buildBook` 返回 `BOOK_CONFIG_INVALID` 诊断并阻止载荷生成；字段路径写入诊断消息；
2. **极端排版内容**：超宽表格、大尺寸代码块或不可分割的超高 SVG 矢量图在进入正文渲染时，可能超出正文页物理尺寸，此类边界情况需依赖运行时的溢出截断策略进行容错；
3. **哈希键值碰撞**：CRC32 的有限键空间可能产生碰撞，不能仅因内容集较小承诺无碰撞。本包仍可能生成重复 key；Runtime 拒绝该载荷而非错误定位章节。调用者须修正上游身份或键生成方案后重新分页，不自动改写既有深链接；
4. **回退与自愈方案**：由于本模块为无状态的静态编译流水线，所有失败均可在修复配置或源文本后，通过重新触发 `npm run build` 实现干净的构建恢复。

## 验证与演进

以下测试覆盖已列出的模型、配置和产物契约；不证明任意输入或所有浏览器下都正确：

- **数据源与装配测试**：由 `packages/site/tests/json-book-source.test.mjs` 与 `tests/integration/book-runtime.test.mjs` 验证数据模型转换、默认值回退、标题剥离与配置深拷贝行为；
- **配置契约测试**：由 `tests/integration/book-config-schema.test.mjs` 验证 Schema 对合法配置的宽容度与对非法配置的拦截准确性；
- **主题样式测试**：由 `packages/book-build/tests/book-theme.test.mjs` 验证测量选择器派生算法的准确性；
- **产物契约测试**：由 `tests/integration/book-runtime-boundary.test.mjs` 核对书壳与模块边界源码约定；该文件不是浏览器交互验证。

- 未来演进规划：若引入不可信投稿或外部内容源，应先确定允许的 HTML、URL 和净化责任，再选择净化方案并建立攻击夹具；
- 当前未实施该能力；
- 若书籍章节规模进一步扩张，可考虑将 CRC32 短哈希升级为抗碰撞能力更强的分片索引策略。
