# ADR 0003：类型化文档契约与模块归属

本记录保存当时完整决定；目录、旧入口、Schema中转和重定向策略已由 [ADR 0004](0004-physical-modules-and-public-api.md) 替代。当前实现以新决定和模块API为准。

## 背景

仅规定“说明设计与风险”不能指导作者完成章节。相同类型目录不同，模块 README 不独立，专项内容集中根 docs，历史尺寸与当前配置混杂，导致读者无法定位权威资料。用户批准同时改语言、章节、元数据、图、README 和归属。

## 备选方案

| 选择                         | 收益                     | 代价                                       |
| ---------------------------- | ------------------------ | ------------------------------------------ |
| 一套目录套全部文档           | 工具简单                 | 操作、参考和算法的读者任务不同，强套会填空 |
| 作者自由组织                 | 局部灵活                 | 同类内容难比较，缺少可执行最低要求         |
| 按类型固定章节，三级章节裁剪 | 同类可比较、内容仍能展开 | 需维护类型约束并审查章节实质               |
| 迁移独立文档平台             | 搜索与展示可增强         | 引入发布链、版本和工具成本，不解决内容空洞 |

## 决定

保留仓库 Markdown，按八种主要类型规定章节及验收，辅助类型单独裁剪。九字段 YAML 元数据定义身份、状态、范围、责任和关系；Git 保存作者及历史，不复制版本号、提交号和评审状态。日期是本轮正式版本建立及实质修改时间。

模块拥有专项算法、接口、配置参考与操作。根 docs 保存跨模块设计、协议、共享标准、全局测试和交付协调。旧路径留 deprecated 导航，不复制完整内容。历史原件保留时点信息并明确排除当前契约。

机器检查字段、日期、章节、标识唯一、关系、链接及生成漂移；人工核对源码事实、复杂度依据、图的含义、例子和实际读者任务。

## 后果

作者可按文档类型逐章验收，模块读者无需先遍历根 docs；生成参考来源与模块责任一致。前置元数据在某些 Markdown 阅读器中显示成原文，仍可直接解析，暂不增加文档站依赖。

格式检查不证明技术正确；Mermaid 源码需要人工审查及阅读平台支持。packages/book-runtime/docs 属于公开静态资产，不能写内部凭据。已有历史记录只补身份元数据，不追溯改写当时章节和验证结论。

## 再评估条件

出现全文检索、权限隔离、版本化 API 或多团队维护需求时评估文档站；不要先为了展示工具迁移全部资料。变更章节或元数据字段需同步本规范、检查器、回归测试和受影响当前资料。新增主要类型必须证明现有类型不能满足读者任务。
