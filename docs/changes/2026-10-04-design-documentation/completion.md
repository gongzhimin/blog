### 两阶段独立审查

规格阶段核对用户要求和读者任务；事实/质量阶段抽核实现、配置、测试及工作流。作者自查之外，由其他文档组的审查者阅读实际文件；审查者不以实现者报告作为证明。

审查发现并闭环复核的三项重要问题：

1. 发布教程更名后仍断言旧路径存在。改为完整可执行变体，断言新路径、新日期和旧资产不受影响，实际执行通过。
2. Runtime 将两宽度分页测试关联为强调标记语义保留证据。收窄为全文连续和高度，明确跨拆分强调标记缺独立断言，设计、教程和测试策略同步。
3. Site 草稿过滤误写为 source 单测覆盖。改为实现与教程断言，明确现有单测缺口，并与日期排序证据分开。

## 剩余限制

- 编写规则要求写现状依据而非主观担保，但文字仍受编写者认知限制。
- 自动化工具只能验证格式、结构、死链和生成漂移，无法全自动验证所有自然语言描述的准确性。
- 未运行真实 GitHub 写入、服务重启、生产健康、恢复演练或 Safari/iOS 真机；未联网检查全部外链，未验证全部锚点。静态门禁不证明运行隔离，人工抽核不等于逐行审计所有实现。
- 生成配置资料保留来源，不手工改表。历史保留时点，不用当前说法覆盖过去。后续贡献按 [工作流](../../guides/contributing.md) 引用质量场景并同步受影响资料。
